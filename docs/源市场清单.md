# 源市场清单：一份清单和一份源，不是同一种东西

2026-10-18 起，最后更新 2026-10-21。

用户在「设置源」里贴的地址可能是两份完全不同的东西：

```text
一个源      {origin|web} / {code,list,class} / 站点首页 URL
一份清单    {sources:[{name,desc,url}, …]}        ← 这个文档讲的就是它
```

清单里装的是**源的目录**，不是源本身。两者贴进同一个输入框，所以必须先分清再处理。

---

## 一、Java 侧：认出来就抛一个固定串

`UserSource.load(url)` 的第二轮按响应形状识别，`sources[]` 排在最前面：

```java
if (fetched.has("sources")) {
    throw new IOException(MARKET_LIST);      // "MARKET_SOURCES"
}
if (fetched.has("urls"))  { throw new IOException("这是 TVBox 多仓配置…"); }
if (fetched.has("sites")) { throw new IOException("这是 TVBox 单仓配置…"); }
if (fetched.has("origin") || fetched.has("web")) return fetched;
throw new IOException("认不出这是什么配置 —— 既不像我们自己的 JSON，也不像苹果CMS 接口");
```

为什么用**抛异常**而不是返回一个带 `market` 字段的对象：`set` 这条桥的返回值只能是
`{ok, error}` 这种两三个字段的 JSON，前端只认这两个；把清单塞进成功分支意味着
`user-source.json` 已经被写坏了才发现不对。清单不是源，它压根不该走到「保存配置」
那一步，抛出去是最短的路。

也考虑过新开一条桥指令 `__source:market?url=`，最后没做 —— 见下面 JS 侧那节，
`__source:fetch` 已经能把任意 https 的正文取回前端，多开一条只是多一处要同步维护
的 ID。

---

## 二、JS 侧：先失败一次，再认出清单

`assets/setup.js` 的 `submit()`：

```js
const result = await bridgeCall('detail', { id: '__source:set?url=' + encodeURIComponent(url) });
if (!result || !result.ok) {
  const marketMark = /MARKET_SOURCES/.test(result.error || '');   // Java 已经断言过是清单
  const picked = await offerMarket(url, marketMark);
  if (picked) return;
  showError(marketMark ? '你贴的是一份源清单，但里面没有可用的源'
                       : (result.error || '设置失败'));
  return;
}
```

`offerMarket(url, confident)` 拿 `__source:fetch` 把正文再拉一遍，解析出
`sources[]` 渲染成勾选列表；用户勾完，逐条 `__source:set`，最后一条生效。

**`confident` 这个参数是重点。** 它表示「Java 已经确定这是一份清单」，只在那种情况下
才允许它把失败原因写进错误框。

---

## 三、踩过的坑：静默的 `return false`

第一版是这样：

```js
if (!result || !result.ok) return false;    // ← 这里
} catch (error) { return false; }
```

拉不到就返回 false，调用方继续 `showError(result.error)` —— 于是屏幕上留着的是
**上一条** `set` 的报错。

实际发生的事（2026-10-18 真机日志）：

```text
13:55:09 [http] GET 149.104.21.177.sslip.io/
13:55:25 [source] 源设置异常：SocketTimeoutException: failed to connect … after 15000ms
```

网络超时。屏幕上写的是「拉取失败：认不出这是什么配置 —— 既不像我们自己的 JSON，
也不像苹果CMS 接口」。一个网络问题被显示成格式问题，照着查必然走错方向 —— 连
「市场能不能读」都变得可疑。

所以现在：**`confident` 为真时说出真实原因；为假时闭嘴**，让调用方报原来那条更准确
的（比如贴了个 404 地址，就该看到 `拉取失败：服务端返回 HTTP 404`，不是「这是一份
源清单」）。

`offerMarket` 的四种失败各有一句话：

| 失败点 | 显示 |
|---|---|
| `__source:fetch` 返回 `ok:false` | 这是一份源清单，但没拉下来：HTTP 404 / 只放行 https… |
| bridge 自己抛异常 | 同上，后面跟 `error.message` |
| 正文不是 JSON | 这是一份源清单，但没拉下来：响应不是 JSON |
| JSON 里没有 `sources[]` | 这是一份源清单，但没拉下来：清单里没有 sources 数组 |

## 四、清单文件本身

**生产位置**：服务器 `relay:/srv/cfg/market-spider.json`，对外
`https://149.104.21.177.sslip.io/market-spider.json`。仓库里有一份同内容的
[`docs/samples/spiders/market-spider.json`](samples/spiders/market-spider.json)。

**改的位置**（2026-10-23 起是这条）：

```text
https://149.104.21.177.sslip.io/admin/sources/market-spider.json/edit
```

后台保存会先校验结构、再原子替换、最后在 `/data/backups/` 留一份带时间戳的备份，
审计写 `admin.db`。短写 `/admin/sources/market-spider.json` 不一定命中 —— 路由是
`/sources/{name}/edit`。

后台只能改 `/srv/cfg` **顶层**的 json。`spiders/` 子目录里的配置和 js 不在后台范围，
走 ssh / scp：

```bash
scp <本地>/yhdm.json root@149.104.21.177:/srv/cfg/spiders/yhdm.json
scp <本地>/yhdm.js   root@149.104.21.177:/srv/cfg/spiders/yhdm.js
```

仓库里 `docs/samples/spiders/` 那批是**副本**，改源的时候以服务器上那份为准（先拉下来再
改，别拿可能落后的副本盖上去）。

条目现在指向的是 **spider 配置**，不是站点首页：`…/spiders/<id>.json`。这样一条清单就是
三层引用（市场 → 源配置 → js 源码），改完必须跑一遍 `node work/android/scripts/market-check.js
https://149.104.21.177.sslip.io/market-spider.json`，别只改一层，见
[Spider 接入规范 §10.4](spider-接入规范.md)。

服务器上那份老的 `market.json`（条目是站点首页那一代，苹果CMS 接口 + 站点 URL）还在，
客户端也还认；但新加的源一律走 spider 那份。

```json
{
  "updated": "2026-10-21",
  "sources": [
    { "name": "樱花动漫", "desc": "番剧 / 55 卡", "url": "https://149.104.21.177.sslip.io/spiders/yhdm.json" },
    { "name": "MissAV", "desc": "无码流出 / FC2 / 需代理", "url": "https://149.104.21.177.sslip.io/spiders/missav.json" }
  ]
}
```

三条硬约束：

- `sources[].url` 必须是 https，且必须是**能被 `load()` 认出来的东西**（CMS 接口、
  站点首页、配置文件地址都行）
- `desc` 里写「需代理」是给人看的提示，**路由以源配置的 `net` 为准**（当前只有四个源声明了）
- `updated` 改不改都不影响客户端，纯粹给人看

**一条线：做源和上市场是同一次动作。**

2026-10-23 定的规矩：**新做一个源（或改了一个源的地址/说明），必须同时更新
`market-spider.json`** —— 源文件躺在 `/srv/cfg/spiders/` 但市场里没这一条，用户就永远
看不到它。顺序固定：

1. 写 `spiders/<id>.json` + `<id>.js`，跑 `spider-check.js` 的断言；
2. `scp` 上服务器（先备份旧文件）；
3. 后台编辑页在 `sources[]` 里加/改一条 `{name, desc, url}`，保存；
4. 跑 `node work/android/scripts/market-check.js https://149.104.21.177.sslip.io/market-spider.json`；
5. 真机「设置源 → 贴市场地址」，勾上那条，能出首页才算完。

`work/find-sources.py` 是另一件事：扫候选影视线路、实测、生成清单，`--top` 控制影视
线路留几条（**默认 2**，五条线路长得一模一样，多留只是让勾选列表变长）。它只服务
苹果CMS 那一类，不代替上面五步。

清单**存在服务器上，不在 App 里**。App 一个内置源都没有，`assets/` 里也没有任何站点
配置 —— 这是产品上的决定，不是没做完。

## 五、清单里现在有什么（2026-10-21，12 条）

全部是 spider 配置。完整地址看
[`docs/samples/spiders/market-spider.json`](samples/spiders/market-spider.json)：

```text
樱花动漫        yhdm.json       番剧 / HTML 站
AGE动漫         agedm.json      番剧 / 播放要跑站点 wasm
影视线路         cms.json        苹果CMS（一条配置带多站）
Hanime1        hanime1.json    里番
每日大赛         mrds66.json     吃瓜爆料 / 图床白名单
91porn         porn91.json     KVS / 视频
MissAV         missav.json     无码流出 / FC2 / 盾后站
ASMR基佬中心     openlist.json   音声 / 文件站
黄果短剧         huangguo.json   短剧（已不是内置源）
Iwara          iwara.json      盾后站，api 一起在盾后
Pornhub        pornhub.json    服务端渲染，分片认 Referer
51吃瓜          51cg.json       服务端渲染 / AES-128 HLS
```

**别在这张表里写「需代理」了。** 2026-10-19 之后路由由源自己声明（`net.proxy` /
`net.declared`，见[接入规范 §7.1](spider-接入规范.md)），表里写了就会和配置打架。
当前样例里只有四个源声明了它（dozagonza 和 pie 还没上市场清单）：

| 源 | 声明 | 为什么 |
|---|---|---|
| yhdm | 只代理 `yhdm.one` | 播放 CDN 九成在境内，全走代理反而 403 / TLS 被掐 |
| huangguo | 只代理 `huangguoai.com` | 2026-10-20 更正：入口域直连被 reset，只能走节点；图床和播放 CDN 仍直连 |
| dozagonza | 显式全直连（`proxy: []`） | 开代理时站点直接 `ERR_CONNECTION_CLOSED` |
| pie | 代理 15 个接口域 | 接口在墙外，播放 CDN 在境内 |

其余八个源没有 `net` 块，**跟随 App 的全局代理开关** —— 用户没配代理就是全直连。

旧清单里 MissAV 那条 `url` 填的是 `https://missav.live/cn/genres`；现在不带路径了，
识别靠 spider 自己的 host，填什么后缀都不影响探测。

## 六、怎么验

真机上最省事的办法是把页面接进 Chrome DevTools（见
[真机 WebView 调试](真机WebView调试.md)），然后直接调桥：

```js
await bridgeCall('detail', { id: '__source:fetch?url=' + encodeURIComponent('https://149.104.21.177.sslip.io/market-spider.json') })
```

返回 `{ok:true, body:"{…}"}` 就说明清单本身没问题。接着走完整流程：

```js
document.getElementById('setup-input').value = 'https://149.104.21.177.sslip.io/market-spider.json';
await window.HGSetup.submit();
document.querySelectorAll('.setup-market-check').length   // 应该是 12
```

反例也验一遍：贴一个 404 的地址（`…/nope.json`），错误框里应该是
「拉取失败：服务端返回 HTTP 404」，不是市场那套话。
