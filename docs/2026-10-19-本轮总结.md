## 一、五层拆分（10-18）

出发点是接樱花动漫时连修五个 bug，**没有一个在解析逻辑里**：探针没认出来、
选集格子全是 `undefined`、上游 200 但 VLC 说 cannot peek、选集点第 3 集请求打到
ep1、线路全 403。共同点是一句话：**站点知识散落在互不知情的层里**。

于是按「层」拆，不是按文件拆：

| 层 | 之前 | 之后 |
|---|---|---|
| 适配器 | 八家各 800~1100 行，HTML 工具各抄一份 | `HtmlKit` 293 / `AdapterShape` 130 / `AdapterIo`，八家合计 **-469 行** |
| 网络路由 | 四个 OkHttpClient 工厂 + 一个全局代理拖所有请求 | `ProxyRoute` 226（值对象）+ `NetRoute` 180（按源决定直连/代理） |
| 桥 | `detail` 一条万能隧道，五个前缀挤里面 | 六条并列前缀，dispatch 是一张 Map，顺序无关 |
| 控制面 | `UserSource` 2492 行、七个子系统 | **576** + `SourceConfig` 1110 / `ProxyConsole` 678 / `PlayerControl` 332 / `PlaybackHttpBridge` 75 / `ProgressSink` 63 |
| 播放器 | `VlcPlayerActivity` 1930 行 | **1644** + `VlcControlsView` 528 + `VlcSession` 152 |
| 前端 | `app.js` 4256 行、270 个顶层声明 | **3494** + `proxy-panel` 408 / `source-market` 439 / `app-update` 141 |

三条拆分原则，后来每一步都在用：

1. **注释跟着声明走**。按顶层声明切块时，注释块属于下面那个声明；否则每块开头
   的解释会粘到上一块尾巴上，跟着搬错文件。
2. **切完逐块断言「原文这一块在新文件里恰好出现一次」**。270 块，丢失 0、重复 0。
3. **只有单一入口的整屏才搬得走**。代理页只有一个入口（`goProxySettings`），搬了；
   路由层被 18 个函数调用，没搬 —— 那是改结构，不是搬代码。

## 二、spider 运行时（10-19）

### 为什么是这个形状

| 决策 | 选择 | 决定性理由 |
|---|---|---|
| 执行引擎 | WebView | TLS 指纹。一半的源卡在 Cloudflare，Rhino/QuickJS 过不去 |
| 数据模型 | 自己的 15 个角色 | `web.fields` 早就是它的雏形；`Vod` 的分隔符编码表达不了线路优先级 |
| TVBox 兼容 | 只做入站 + JS 垫片 | 不碰 `DexClassLoader` |

沙箱是四条 CSP 各挡一件事：`connect-src 'none'`（spider 自己发不出请求）、
`img-src 'none'`（堵 `new Image().src` 外带）、`frame-src` / `form-action` / `base-uri`。
网络只走 `__spider.call('net')`，主机必须是源自己声明的 `hosts`。

### 三阶段的实际产出

| 阶段 | 产出 | 真机证据 |
|---|---|---|
| 0 | 宿主页 58 行 + `SpiderRuntime` 813 + `SpiderBridge` 100 | `cap=home ok ms=469`；超时 3s 杀掉宿主后同进程 31ms 重建 |
| 1 | `yhdm.js` 382 行、`SpiderStore` 635、内容源页的 spider 列表 | `樱花动漫 · 55 卡 / 2 集 / 13 备选 · 5.6s` |
| 2 | `model.js` 256（转换层）、源可只有 `web.spider`、前端通路分岔 | 首页/详情/播放全走 spider，`/api` **零请求** |
| 3 | 源只剩一个来源（用户装的） | `src=user`，spider 列表 1 条 |

**「加源不发版」这件事现在是闭环的**：贴 `https://…/yhdm.js` → 下载校验落盘 →
当普通源用。信任边界和 TVBox 一样（边界是「你装了什么」），区别是 TVBox 下发
可执行 dex，我们下发跑在 CSP 沙箱里的 js。

## 四、这一轮踩过的坑（按代价排序）

1. **判「黑屏」不能只看截图。** 真机滑到第 2 集，`screencap` 连着三张纯黑图，
   实际在解码（`VideoFrameStats enqueued=48 acquired=47`）。现在规矩是：先看
   `VideoFrameStats` / `AudioTrack`，再用 `screenrecord` 抽帧。
2. **「两个真相」这一类 bug 会反复出现。** 路由表说走代理、建客户端读全局设置；
   修了三次才彻底（`NetRoute` 决策 → `routeForProxyHost` 等核心 → `net` 请求前等待）。
3. **契约里的双重编码。** 驱动脚本传 `JSON.stringify(r)`，`call` 内部又 stringify
   一次，Java 收到字符串字面量 —— 不崩，只是每次都超时。
4. **`indexOf("__spiderSite")` 命中了注释里的同名提及**，接着找到的 `{` 是别的
   函数体，四个字段全 null。扫描必须跳过注释 / 字符串 / 正则字面量。
5. **数组长度会变，游标不会。** 换线时过滤掉「当前这条」，数组缩水而游标照走，
   第二条备选永远试不到。
6. **删方法的边界不能靠缩进猜。** 一次贪心的切片把 `lambda$onCreate` 那几个方法
   一起删了，报错全指向别处。现在只按「起止两个方法头」取，并且先打印要删的块。
7. **设备会自己锁屏**，`screencap` 返回纯黑、`input swipe` 解不开 —— 别把
   「黑屏」当代码问题。

## 五、现在的形态

```
源（spider，用户装的）
   ↓  前端 api() 检测到 web.spider
spider 桥 → SpiderRuntime（WebView，CSP 锁死）
   ↓  __spider.call('net')
AiiHttp → NetRoute（按源声明决定直连/代理）→ DoH → 上游
   ↓
HGModel（转换层）→ app.js 渲染 → VLC 播放
```

**两条并存的路**：REST 源（八个内置适配器 + 苹果CMS）仍然走 `web.paths` →
`/api/*` → 适配器。`web.paths` 的**默认值**已经删了，机制还在 —— 因为删了那八家
会同时失效。

## 八、这份工作的一个判断

真正被反复验证的一件事：**bug 的长度和信息散落的层数成正比**。
这一轮里最贵的几个问题（线路全 403、选集点错集、首页空着、spider 取不到数据）
没有一个出在「解析写得不对」，全部出在「同一件事有两个读取点」。

所以拆分的价值不在行数，在于**让每个决定只有一个地方能改**：
路由只在 `NetRoute`、代理串只在 `ProxyRoute`、字段名只在 `web.fields`、
模型只在 `model.js`。行数变少是副产品。
