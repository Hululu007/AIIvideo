# 前端热更新使用说明

改 HTML / CSS / JS 不用再打 APK，也不用发 GitHub Release。流程是：

```text
本地改 assets → publish-hot.sh 打签名包 → scp 到自己的服务器
→ App 启动/设置页检查 → 下载验签 → 下次启动切换
```

APK 只在动 Java / smali / 原生资源时需要重打。

## 1. 服务端放哪

账号后端那台机器（`149.104.21.177`）的 Caddy 已经把 `/*` 映射到 `/srv/cfg`：

```text
/srv/cfg/hot/hot-update.json        ← 最新清单（客户端只读这一个地址）
/srv/cfg/hot/resources-r<rev>.zip   ← 对应版本的前端包
```

公网地址：

```text
https://149.104.21.177.sslip.io/hot/hot-update.json
```

这个地址写在 `HotUpdateManager.smali` 的 `INDEX` 和 `check()` 里。换域名要改这两处并重新打 APK
（或者把域名做成构建参数，但热更新通道本身必须有一条固定的入口）。

Caddy 不用额外配置；确认 `/hot/` 能直接访问即可：

```bash
curl -I https://149.104.21.177.sslip.io/hot/hot-update.json
```

## 2. 怎么发一版

```bash
cd work/shells

# 只生成到 work/shells/hot-out/
./publish-hot.sh

# 生成并上传（默认 relay:/srv/cfg/hot）
HOT_UPLOAD=1 ./publish-hot.sh

# 指定版本号（revision 必须比上一版大；version 只用于显示）
REVISION=1006 VERSION=2026.10.18.1 HOT_UPLOAD=1 ./publish-hot.sh
```

`publish-hot.sh` 会：

1. 从 `cz_repack/assets/` 复制前端到临时目录；
2. 排除 `hot-update-public.pem`、`site-default.json`、`dexopt/` 这类不能热更新的文件；
3. 现算一份 `site-web.js`，避免发旧配置；
4. 打 `ui/` + 根 `site.json` / `theme.json` 的 zip；
5. 用 `.build/brandkey/aiivideo-hotupdate-private.pem` 签 ECDSA；
6. 校验签名、包路径、sha256；
7. 先传 zip，最后传 `hot-update.json`（客户端不会拿到指向不存在文件的清单）；
8. 只保留服务器上最近 5 个 zip。

## 3. 客户端什么时候生效

- App 每次 `onResume` 会检查一次，30 分钟内不重复；设置页「检查更新」是强制检查。
- 下载、验签、解包成功后进入 `pending`，不会立刻打断当前页面。
- **下次冷启动**自动把 `pending` 作为 trial 加载；设置页也可以点「立即应用并重启」马上切。
- 新界面在首页真正渲染出来后调用 `hot-ready`，trial 才算健康。
- 如果新界面启动失败/超时没 ready，下一次启动会自动回退到上一版，并把该 revision 记为
  `blocked`（设置页会显示「rX 没能正常启动，已回退」）。发一个更高 revision 的包即可覆盖。

## 4. 包结构

```text
site.json          {}                  ← 只保留 APK 内置站点配置，不覆盖用户源
theme.json         {"enabled":false}   ← 不启用远端主题
ui/
  app.html
  app.css
  app.js
  card-transition.js
  runtime.js
  site-web.js
  setup.js
  feed-player.js
  cover.js
  adapters.js
  vendor/
  hxm/
  *.svg
```

`HotUpdateManager.resource()` 会把 `appassets.androidplatform.net/assets/<path>` 优先映射到
`<session>/ui/<path>`，找不到才回落到 APK 内置 assets。因此整包前端都在 `ui/` 下。

阶段限制（`stage()` 里写死的）：

- 最多 512 个文件、解压后 26 MB；
- 只收 `ui/`、`theme/`、根 `site.json` / `theme.json`；
- 只收 `.html .css .js .svg .png .jpg .jpeg .webp .gif .json .woff .woff2 .txt`。

## 5. 密钥

- APK 里只有公钥：`assets/hot-update-public.pem`。
- 私钥在本地：`work/shells/.build/brandkey/aiivideo-hotupdate-private.pem`，**不要提交、不要上传**。
- 换私钥 = 换公钥 = 必须重新打 APK；旧包会全部验签失败。
- 服务器被入侵也只能改包的内容，改不了签名；客户端验签不过会直接拒绝。

## 6. 边界

这条通道只能改前端资源。下面这些仍然必须重打 APK：

- `smali/` 里的 Java 逻辑、Manifest、原生资源；
- `classes5.dex` 里的 `java-src/`；
- 新增/修改打包进 APK 的权限、Activity、Service。

另外，`site.json` / `theme.json` 在包里留空是刻意的：这个 App 的内容源由用户自带，
热更新不应该覆盖用户当前选的源。站点规则确实要下发时再单独设计。
