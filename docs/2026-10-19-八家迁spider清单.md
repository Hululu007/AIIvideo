## 四、一个必须提前想清楚的点

`YhdmAdapter.probeLine()` 在探测线路时有个副作用：**把能直连的分片域名登记进
`DirectHosts`**。这是它能播的关键 —— 那一族 CDN 走代理反而死。

这段逻辑搬到 spider 之后**做不到**：宿主页没有 `DirectHosts` 这个能力，而给
spider 开一个「改全局路由表」的口子，等于让一份用户装的 JS 能改全 App 的网络走向。

三条出路，选一条（别默认选第一条）：

1. **让源声明**：spider 的 `__spiderSite` 加一个字段 `direct: ['kkzycdn.com', ...]`，
   `SpiderRuntime` 在注入后读一次，登记进 `DirectHosts`。口子开得窄（只能加，不能删，
   只能本域名，不能通配），而且「哪个站需要直连」这件事写在源里，和 `hosts` 是同一种声明。
2. **不探测线路活力**：spider 版直接给全部 alts，让播放器的线路竞速去挑
   （`LineRace` 已经有这套）。代价是起播慢一两秒，但不用开任何口子。
3. **`DirectHosts` 内置那批域名**：把实测过的 16 个采集站域名写死在 Java 里。
   不推荐 —— 那正是这一轮在拆的东西（「域名天天换，白名单追不上」）。

写代码前先决定，不要中途换。

### 过程中发现的真 bug（都不是「写错一个字符」那类）

1. **missav 无 `g` 标志正则进 `exec` 循环 → 进程永久挂死。** `P_QUALITY` 是 `/…/i`，
   而代码写 `while ((m = P.exec(s)) !== null)`。第一次匹配成功后 `lastIndex` 不推进，
   原地打转。我跑 `spider-check` 六十秒不回来，就是它。
   同型问题一共三处（`P_QUALITY` / `P_GENRE_ID` / `meta()` 里那个模块级全局正则
   被高频重入后 `lastIndex` 互相打架）。
2. **回归脚本单源模式没有超时保护。** 一上那个死循环，整条命令永久挂住。
   加了 `Promise.race` 也没用 —— 计时器是宏任务，同步死循环占住事件循环时轮不上。
   最后改成每个 cap 一个子进程 + `spawnSync` + SIGKILL 才真杀得掉。
3. **openlist 递归采集缺 visited 守卫。** AList 的 `fs/list` 对某些路径会回成同一批
   内容，同一个文件被收成好几份剧集。
4. **跨源 `episode` 拼接错误。** app.js 一律拼 `id:epN`，但 missav 的 ref 就是 id 本身，
   拼成 `abc:ep1` 会 404。**这个 bug 只有八个源同时存在时才暴露** —— 单源时代每个
   适配器自己拼 URL，错了只错一家；ABI 统一之后 `ref` 的语义成了跨源契约，
   而契约没被校验。
5. **`web.spiderArgs` 缺失（我自己引入的缺口）。** `cms.js` 从 `args.api` 读接口地址，
   而 `spiderArgsFor` 从来不传配置项 —— 于是「配置里写 `web.api`」是死的，源一直用
   兜底域名跑，**表面完全看不出问题**。补了 `web.spiderArgs` 声明机制。

第 1、2 条是工具层的问题，第 3、4、5 条是语义层的问题。**第 4、5 条都属于同一类：
「一个概念在两边各有一份实现，而没人校验它们一致」。** 这是统一的代价，不是统一的失败。

## 八、net 的二进制缺口（下一轮要补）

这一轮做完才发现，`net` 有个比「缺个参数」更根的问题：**它传不了二进制**。

```java
out.put("body", new String(raw, charset));   // SpiderRuntime.net 的最后一步
```

一个 1.3MB 的 ts 分片走 UTF-8 解码，非法字节全变成 U+FFFD。JS 拿到的
`body.length` 是「替换符个数」，不是字节数 —— 而且这个映射是**一对多**的
（一个坏字节不保证只变一个替换符），所以正反两个方向都对不上。

后果：源没法判断「这个地址到底活没活」。yhdm 的线路探测因此在这一轮被**有意放弃**
（见 `yhdm.js` 文件头那张表），代价是「第一条线路是死线」时用户点了播不了。

**补法（两样，都很小）：**

1. `net` 加可选入参 `range: {from, to}`，转调 `AiiHttp.getRawRange`
   （**这个方法已经存在**，`AiiHttp.java:944`）。
2. 返回值加一个 `bytes`，取自 `raw.length`，**必须在 `new String(...)` 之前取**。
   不要用 `body.length` 顶替 —— 那正是现在判不出来的原因。

判定就变成 `res.bytes >= 1024`。一次 Range 只取前 2KB，几十毫秒。

**别加「body 是否被解码坏了」的布尔标记。** 判非法字节要 `CharsetDecoder` 配
`CodingErrorAction.REPORT`，而 `new String()` 那版永远静默替换、永远不报错。
一个数字够用：二进制场景源只认 `bytes`，文本场景源只认 `body`。

**预算不用担心。** `getRawRange` 走的也是 `rawWith`，所以同样会重试一次；
但 2KB 的 Range 重试一次仍是几十毫秒 —— 之前「一次失败 30 秒 × 6 次撞 45 秒超时」
那个估算在 Range 成立之后自动消失。

**还有一个前置坑**：「探 CDN 分片」要求 net 白名单里有那些 CDN 域，而现在
`yhdm.js` 的 `hosts` 只有 `yhdm.one`，探 CDN 会先被 `net 拒绝：主机不在白名单`
挡掉。补 range 的那一轮要一起处理 —— 但不能简单地「把 16 个采集站域名写进 JSON」，
那正是这一轮在拆的东西（域名天天换，白名单追不上）。可行方向是让源声明
`direct` 前缀域或者按需扩展，写代码前先定方案。

## 九、net 看不见非 2xx 的正文（比上面那条更基础）

```java
if (!response.isSuccessful()) throw new IOException("HTTP " + response.code() + " @ " + url);
```

`AiiHttp.rawWith` 在非 2xx 时直接抛异常，**不把 Response 交出去**。于是 `net`
永远拿不到 4xx/5xx 的**正文**，只能报一句「HTTP 403 @ …」。

后果不是「少了点信息」，是**源没法判断自己撞上了什么**：

| 实际发生的事 | 源看到的 | 两者该有的处置 |
|---|---|---|
| 站点套了 Cloudflare 盾，回了 403 + 挑战页 | `HTTP 403` | 换源 / 换网络 |
| 站点改版，回了 404 + "not found" | `HTTP 404` | 换源 |
| 分类 id 传错，回了 500 + 错误 JSON | `HTTP 500` | 改参数 |
| 签名过期，回了 403 + "auth expired" | `HTTP 403` | 重新取签名 |

这四种在 net 里长得**一样**，而给用户的建议完全不同。

实测证据（2026-10-19，`www.asmrgay.com/api/fs/search`）：
```
status=403  正文 5463 字节  含 "Just a moment"  → 是挑战页
```
openlist 的 `looksLikeChallenge` 判据是对的，但它**永远走不到那一步** ——
`res.ok !== true` 时 `res.body` 根本不存在。

**补法**：`net` 加一个可选入参 `non2xx: true`（缺省 false，保持现有行为）。
为 true 时，非 2xx **不抛**，而是按 `{ok:false, status, body}` 返回正文。
`status` 字段顺便就有了 —— 阶段 0 契约里那句「status 报不出 4xx/5xx」也就解除了。

注意这是**可选**而不是改默认：现有源都按「失败只可能是网络问题」写的，
改默认行为会让它们的错误处理全部失效。

### 这一轮的临时处置

openlist 先按「2xx 也可能拿到挑战页」写了判定（有的 WAF 用 200 回挑战），
并在 `res.ok !== true` 分支里也加了一次 `looksLikeChallenge(res.body)`——
**这段现在是死代码**，等 `non2xx` 落地才会生效。留着是因为它写的是对的，
删掉的话下次补运行时还得重推一遍。代码里有注释说明这一点。

## 十、真机上线那一路踩到的（2026-10-19 下午）

第八、九节是「拆完发现的缺口」，这一节是「装到手机上才发现的问题」。
两者不重叠：拆完代码是干净的，装进真机才暴露下面这些。

### 10.1 市场地址填错了

```
/admin/...  → 401    ← 这是后台界面，挂着 basic_auth
/market-spider.json → 200
```

`market.json` 和 `market-spider.json` 都在站点根（`file_server` 直接服务）。
`/admin/` 底下是后台管理界面，App 拉不到。

新市场的地址：`https://149.104.21.177.sslip.io/market-spider.json`

### 10.2 路由自相矛盾 → 45 秒超时

```
[source] net yhdm.one → 代理 profile=有 mode=direct proxy=空
[source] net 等核心就绪 3007ms → 仍为空，按直连发
HG.Spider: cap=home timeout 45000ms
```

源声明 `net.proxy: ["yhdm.one"]`，而全局是 `mode=direct`。于是：

- `directOnly` 说「不在直连表 → 不该直连」（false）
- `mustProxy` 说「在代理表 → 该走代理」（true）
- `effectiveProxy()` 是空串，**谁也给不出代理**

请求就这么空着，直到超时。

**修法**：`NetRoute.proxyUnavailable()` 识别这种情形并按直连放行 ——
可以失败，不能什么都不做。日志也改成明说「无代理可用（源声明要走代理，按直连发）」。

顺带发现 `NetRouteTest` 那两条断言一直活在「声明了代理就一定存在代理」的假前提上：
单测环境永远没有代理，所以它测不到真机上那个失败模式。改了断言，现在两种语义都钉住。

### 10.3 spider 源装不上源码 → 「找不到 spider: xxx」

`addSelected` 只调了 `source set?url=`，**从没装过源码 js**。
spider 源的配置里只有一句 `web.spider`，解析逻辑全在 js 里。

**修法**：`setup.js` 加 `addOneSource()`，装完配置读 `web.spider`，按第八节那套规则
去下源码。两个入口（设置页、源市场）共用同一个函数。

### 10.4 release 包签名冲突

```
INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match
```

设备上装的是 release 签名的包，`assembleDebug` 出来的是 debug 签名（Android 默认
debug keystore）。装不上去。

**出 `assembleRelease`**，签名来自 `keystore.properties` 指的 `cz.keystore`。

### 10.5 AGE 播放：四个坑

已经在 `2026-10-19-AGE播放链路四个坑.md` 里单独写了一份。摘要：

| # | 症状 | 根因 |
|---|---|---|
| 1 | 「N 条线路都试过了」 | `resolveAny` 要二元数组，`model.js` 给对象数组 |
| 2 | 「没有声明播放层出口（http.hosts）」 | 配置漏了 `http.hosts`（和 spider 的 `hosts` 是两个出口） |
| 3 | `Failed to create demuxer` | `.jpg` 伪装后缀，VLC 按后缀选 demuxer |
| 4 | `Code=9` | **不是 bug**，解析站拒了那条线路 |

第 3 条的修法对别的源同样有效（OpenList 那种「视频改名成 .jpg/.woff2」的站吃同一条）。

## 十二、市场文件怎么保持最新

`market-spider.json` 是三层引用的最外层：

```
市场 {sources:[{url}]}
  → 源配置 {web:{spider: '<js 地址>'}}
    → js 源码
```

**任何一层写错，症状都是「用户点了，然后什么都没有」**，而三层里每一层单独看
都是合法 JSON。2026-10-19 就同时踩过两个：市场里写 `/admin/...`（后台界面，401）、
配置里 `web.spider` 是纯 id（靠同目录猜）。

所以有 `scripts/market-check.js`：

```bash
cd work/android
node scripts/market-check.js https://149.104.21.177.sslip.io/market-spider.json
```

它把三层全走一遍，检查：

| 层 | 查什么 |
|---|---|
| 市场 | 能解析、`sources` 非空、每条有 name 和 https url、不是 `/admin/` 路径 |
| 源配置 | 能 200 拿到、`web.spider` 是个完整 https 地址（不是纯 id） |
| 源码 | 能 200 拿到、沙箱里能加载、导出 `__spiderSite`、id 与文件名一致、`hosts` 非空、五个能力都在 |

**改完服务器上任何一份文件，跑一次这个。** 它比在手机上点八遍快，而且能查出
「点进去才知道」的那种错。

另外两个已有的回归配合着用：

```bash
node scripts/spider-all-check.js   # 八源离线回归（有夹具的才断言）
node scripts/spider-id-check.js    # web.spider 两种写法 → id
node scripts/model-check.js        # spider 输出 → 前端形状
```

### 内容准确性也要盯

市场里的 `desc` 是给人看的，但**说错了会误导人做判断**。2026-10-19 修过一条：

```
旧：spider · 番剧 / 46 个类型词 / 播放地址加密（播不了）
新：spider · 番剧 / 45 个类型词 / 播放要跑站点 wasm 解 age_ 密文
```

「播不了」在当时是对的（密文解不开），但修完 `.jpg` 伪装之后已经能跑到解码器了。
**desc 跟着能力走，不跟印象走。**

（顺带：类型词数了一遍是 45 不是 46。之前那个 46 是照着 Java 常量数出来的，
`AgedmAdapter.LABELS` 实际 45 项。这种小数字错了没人会去核，写的时候得真数。）
