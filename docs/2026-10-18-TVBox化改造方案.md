# TVBox 化改造方案 —— 把爬虫层搬出 APK

目标：APK 只当壳，源实现全部走热更新。加一个源不碰 Java、不重新签名发版，别人可以独立提交。

---

## 一、现状与 TVBox 的差异

| 维度 | TVBox | 当前工程 |
|---|---|---|
| 源实现载体 | jar（dex 动态加载）/ JS / HTTP API | Java 类，编译进 APK |
| 热更范围 | 爬虫可换 | `ui/` `theme/` 下的前端资源 |
| 能力接口 | homeContent / categoryContent / detailContent / searchContent / playerContent | `SiteAdapter` 六个元数据方法 + `fetch(profile, "/api/...")` |
| 抽象点 | 统一内容模型（Vod） | 内部 `/api` 动作路径词汇表 |
| 加源成本 | 拖一个 json 进来 | 写 Java 适配器 + 发 APK |

根本差异在最后两行。TVBox 的词汇表是固定的，语义写在源里；我们的词汇表本身就是扩展点，所以「加一种语义」等于「改代码」。

`CmsAdapter` 是个好例子：它其实是 TVBox 苹果CMS 协议的完整实现（`home`/`category`/`detail`/`search`/`play` 都在），但最后还是得出 `{"data": …}` 的内部形状。翻译层做在了错的一侧。

### 现在的真实数据通路

```
app.js  ──按 HG_SITE.paths 拼 URL──>  bridge('detail', {id: url})
        <── JSON.parse 后直接消费 ──  SiteRepository.detail
                                          └─ AiiHttp.get(url, profile)
```

`SiteRepository` 其余方法全是 `throw UnsupportedOperationException`（抓 HTML 的分支已删）。语义分散在三处：

1. `site-default.json` → `paths` / `fields` / `ui`
2. `app.js` → `adaptHome` / `nextPageOf` / 各 render 函数里对响应形状的假设
3. `*Adapter.java` → 非 REST 源（CMS、OpenList）

## 二、唯一的硬编码障碍

`UserSource.java:122`（后来那一段搬到了 `PlaybackHttpBridge.java:30`，写法没变）

```java
private static final String[] HTTP_HOSTS = {
    "jx.wuzhoupai.com",
    "xcdn.khfed.com",
};
```

`http()` 桥按这个白名单放行。JS spider 抓任意站必须先拆掉它。

> **2026-10-18 晚更新**：这两行已经搬进配置了，见 §4.1 的落地情况。
> 现在 Java 里没有站点域名，只有「当前源声明的表」。

## 三、热更新层已验证可承载爬虫

`HotUpdateManager.unpack()`：

```java
if (!entry.getName().matches("(?:ui/|theme/).*|site\\.json|theme\\.json")
        || !entry.getName().matches(".*\\.(html|css|js|svg|png|jpg|jpeg|webp|gif|json|woff|woff2|txt)$"))
```

- `ui/spiders/*.js` 通过
- `site.json` 通过，且会过 `new SiteProfile(context, site.json)` 校验
- 上限：512 条目 / 25MB 解压 / 签名信封 + sha256
- 读取：`inside(directory, str.startsWith("theme/") ? str : "ui/" + str)` —— 非 theme 一律落 `ui/`

现有工具：`HG_HTTP`（任意 HTTP 走桥，受白名单限制）、`HG_HXM`（TinyGo wasm 黑盒）、`SiteFetchWebView`（过 Cloudflare）、`AiiHttp`（DoH / 代理 / h2 降级 / 预热）。

## 四、一次性地基（唯一需要发 APK 的版本）

发一版之后 spider 全部走热更。四个改动，全部集中在桥的入口。

### 4.1 网络授权配置化

> **落地情况（2026-10-18 晚）**：最小的一步已经做了 —— `HTTP_HOSTS` 常量删掉，
> 换成源配置里的 `http.hosts`（精确匹配、只放行 https、**没声明就全拒**），
> 由 `SiteProfile` 构造时装进 `PlaybackHttpBridge`。AGE动漫 在自己的
> `buildConfig()` 里声明了那两台机器，老配置由 `AgedmSite.patch()` 补。
>
> 还差的两块留给真正的 spider：**通配符**（`*.example.com`）和
> `allowAnyHost` 逃生门。它们不急 —— 现在没有任何东西需要抓任意站，
> 而一个默认打开的全放行就等于把这面墙拆了。

`HTTP_HOSTS` 常量换成 `SiteProfile` 里的 `net.allowHosts`：

```json
"net": {
  "allowHosts": ["{origin}", "jx.wuzhoupai.com", "*.example.com"],
  "allowAnyHost": false,
  "allowHttp": false
}
```

`http()` 校验改成读 profile。spider 声明自己要抓哪些 host，配置随热更下发。留一个 `allowAnyHost` 逃生门，需要用户显式开启（不是默认，防止随便一个源把设备变成代理出口）。

### 4.2 拆出 `__spider:` 前缀

现在六个互不相干的子系统挤在 `detail` 一条 action 上（`__source:` / `__progress:` / `__http:` / `__player:` / `__proxy:`）。spider 的网络出口应该是独立的 action，和详情页请求分开：

```
bridge('spider', {op: 'http', url, method, headers, body})
bridge('spider', {op: 'fetch-dom', url})      // 需要过 CF 时走 SiteFetchWebView
bridge('spider', {op: 'decrypt', algo, data}) // 复用 cover / hxm 的解密能力
```

顺带把 `detail` 还原成只处理详情。

### 4.3 冻结 spider ABI

写进本文档 §5，之后只加不破。发版前给它一个 `abiVersion`，spider 声明 `requires: ">=1"`。

### 4.4 放宽 `site.json` 校验

`SiteProfile` 的构造器现在强校验 `origin` 必须 HTTPS、`cover.allowedHosts` 非空、AES 参数必须匹配四种之一。spider 源不一定有加密封面，需要让这些字段可选。

## 五、spider ABI

对齐 TVBox 的五个能力，入参出参全 JSON。

```js
// ui/spiders/example.js
registerSpider({
  id: 'example',
  name: '示例源',
  version: '1.0.0',
  abiVersion: 1,
  origins: ['https://example.com'],
  allowHosts: ['cdn.example.com'],

  async home(ctx) {
    const body = await ctx.http.get(this.origins[0] + '/api/home');
    const json = JSON.parse(body);
    return {
      categories: [{ id: 'hot', name: '热门' }],
      list: json.items.map(toVod),
    };
  },

  async category(ctx, { id, page }) { … },   // -> { list, hasMore }
  async detail(ctx, { id }) { … },           // -> { vod, episodes: [{name, flag}] }
  async search(ctx, { key, page }) { … },
  async play(ctx, { flag, id }) { … },       // -> { url, headers, format }
});
```

### 统一模型

```json
{
  "vod": {
    "id": "string",
    "name": "string",
    "cover": "https://…",
    "desc": "string",
    "year": "2026",
    "tags": ["都市", "逆袭"],
    "remarks": "更新至 12 集",
    "episodes": [
      { "name": "第1集", "flag": "m3u8", "url": "", "id": "ep1" }
    ]
  }
}
```

`flag` 的含义和 TVBox 一致：`play()` 按这个标识决定怎么解。内置几个约定值——`direct`（URL 即直链）、`m3u8`、`hls-aes`、`hxm`（走 `HG_HXM`）、`webview`（走 `SiteFetchWebView` 抓）。

### ctx 提供的东西

| 方法 | 说明 |
|---|---|
| `ctx.http.get(url, opts)` | 走桥，受 `net.allowHosts` 约束 |
| `ctx.http.post(url, body, opts)` | 同上 |
| `ctx.dom(html)` | `DOMParser`，HTML 源用 |
| `ctx.json(text)` | 容错解析（去 BOM / 尾部垃圾） |
| `ctx.decrypt(algo, data, key)` | 复用 Java 侧 AES / 自定义算法 |
| `ctx.wasm(name)` | 加载 `ui/spiders/wasm/` 下的黑盒 |
| `ctx.cache(key, ttl, fn)` | 带 TTL 的缓存，防重复请求 |
| `ctx.state` | 该源自己的持久 KV（区分源） |
| `ctx.log(...)` | 进 logcat，带源 id 前缀 |

## 六、迁移路径

每一步都能独立验证，不需要一次性切完。

### 阶段 0 — 地基（发 APK）

§4 的四项。这一版发出去之后不改 Java。

验收：现有功能全部正常（回归 `docs/源市场清单.md` 里的每个源）。

### 阶段 1 — 第一个 spider 跑通（dev-only）

选一个现在的 REST 源，写成 `ui/spiders/huangguo.js`，在调试版里手工加载，不改主流程。

验收：`home` / `detail` 的返回与现有通路逐字段一致。

### 阶段 2 — 内置 spider 接管

把黄果源、agedm、hanime1 逐个包成 spider。Java 适配器保留为 fallback，配置里 `adapter` 和 `spider` 二选一。

验收：删掉 `adapter` 字段后功能不掉。

### 阶段 3 — 前端只认模型

`HG_SITE.paths` 退役，`adapters.js` 的 `pick()` 别名机制收进模型转换层。app.js 不再知道 `/api/videos?cate_id=` 这种路径长什么样。

这一步做完，`web.ui` 里的 `categoryIds` / `categoryLabels` / `categoryTitles` / `categoryLeads` 四张表可以合并成 spider 返回的 `categories`。

验收：换一个 UI 结构完全不同的源，不改一行 app.js。

### 阶段 4 — 源市场

spider 清单独立分发（现在是 `Endpoints.hotIndexUrls()` 那套，可以并列一条 spider 索引）。用户添加源 = 下载一个 spider + 它的 `site.json`。

### 阶段 5 — Java 降到字节层

`*Adapter.java` 全部下线，`SiteRepository` 只剩下载/缓存/封面解密。到这一步，`SiteAdapter` 接口可以整个删掉。

## 七、让别人帮忙维护，实际形态是什么

热更包必须过你的 keystore 签名（`verifyEnvelope` + `hot-update-public.pem`）。所以「别人维护」有两种落法：

**A. PR 模式（推荐，零 Java 改动）**
别人提交 `ui/spiders/xxx.js` + 夹具 HTML，你 review 后打进热更包。绕开了信任链问题，审核成本在代码审查上，不在签名上。

配套要做：
- spider 单文件、无构建、无依赖（只能 `ctx.*`）
- 每个 spider 带一份夹具样本（`test/resources/` 已经是这个形态）
- 一个 `spider-check` 脚本：注入假 `ctx`，跑五个方法，断言出参符合模型

**B. 第三方签名（要改 Java，一次性）**
配置里允许 `trustedSpiders`，每个第三方源一份公钥。适合长期合作方，但要处理密钥分发和吊销，复杂度不划算。

## 八、已知风险

1. **桥是单入口且已有 30 秒超时**（`BRIDGE_TIMEOUT_MS`）。spider 的所有网络都压在这一条上，一个慢源会拖住页面。需要按 op 区分超时，`play` 可以更长，`home` 应该更短。
2. **CSP 是 `connect-src 'none'`**。spider 不能 `fetch`，只能走桥。这条约束必须写进 ABI 文档，否则第一个外部贡献者一定踩。
3. **`SiteFetchWebView` 是 Java 侧能力**，走它需要 §4.2 的 `fetch-dom` op 暴露出来，且要在主线程调度——现在它是 Activity 的一部分。
4. **热更 25MB 上限**。spider 本身不大，但如果一个源要带 wasm 黑盒（像 hxm 那个 307KB base64 膨胀后约 410KB），十几个源就会顶到上限。需要按源拆包。
5. **`site.json` 走 `SiteProfile` 强校验**。spider 源的配置形状和现在不一样，§4.4 不做的话阶段 1 就卡住。
6. **合规面**：spider 由外部提交意味着源地址不受你控制，`allowAnyHost` 的默认值必须关着，否则设备会变成任意站的代理出口。

## 九、如果只做最小一步

`HTTP_HOSTS` 配置化 + `__spider:` 前缀拆出来。两天的事，发一版。

之后所有事都在热更里，包括把现有 Java 适配器一个个换掉——而且换的时候 APK 不用动，随时可以回滚。
