## 一、六个结构

`Site` 是源自己的声明，另外五个是能力函数的返回。

| 结构 | 谁产出 | 字段 |
|---|---|---|
| `Site` | spider 文件顶层 | `id` `name` `version` `requires` `hosts[]` |
| `Card` | `home` / `category` / `search` 的 `items[]` | `id` `title` `cover` `score` `tags[]` `description` `category` `badge` `episodeCount` `duration` |
| `Paged` | `home` / `category` / `search` 整体 | `items[]` `page` `hasMore` |
| `Detail` | `detail` | `Card` 全部 + `description` `episodes[]` `lines[]` |
| `Episode` | `detail.episodes[]` | `no` `title` `line` `ref` `duration` |
| `Play` | `play` | `url` `alts[{line,url}]` `episodeNumber` `reason` `note` |

`lines[]` 在详情里是 `{line, name}`（没有地址），在播放里是 `{line, name, url}`。同一个形状两种填法，因为详情阶段本来就取不到地址——这正是 `Episode.ref` 存在的理由。

`Play.reason` 和 `note` 是**降级通道**，不是错误字段。`reason = 'encrypted'` 的意思是「这一集我认出来了，但地址要在站点自己的 wasm 里解，spider 跑不了」——典型是 `agedm.js`：`url` 留空、`alts` 里给 `agedm-wasm:` 密文标记、`note` 写一句人话。转换层把这三样原样带到输出，并给一个 `state`：

| `state` | 判据 | 上层该做什么 |
|---|---|---|
| `ready` | `url` 是 `http(s)` | 直接播 |
| `declined` | `reason` 非空 | 源说了播不了。有 `agedm-wasm:` 标记就交给 wasm 解析器，否则把 `note` 显示出来 |
| `empty` | 都没有 | 源确实没给地址也没解释，「没实现」落在这一档 |

两种「播不了」必须分开：`declined` 是「这个源认得这一集、但环境播不了」，`empty` 是「这个源就没做」。同一句「没有可用线路」会把排查方向带偏。

这里面藏着一条**源侧的隐含契约**：`reason` 和 `url` 是互斥的 —— 给了 `reason` 就是在说「这一集没有直链」，所以转换层不会拿 `alts[0]` 去补 `url`（`agedm` 的密文被扶正成播放地址，播放器只会报格式不支持）。反过来说，如果一个源既写了 `reason`、`alts` 里又真有一条 `https` 直链、`url` 还留空，现在的输出是 `declined` 加一条列在 `lines` 里但不会被自动播的线路 —— 用户能手动切到它，首播仍判失败。

目前八个源没有这么写的。真出现的那天，改法是明确的：`url` 空时优先从 `lines` 里挑第一条 `http(s)` 扶正（`state` 落回 `ready`），`reason` 降级成给用户看的一句附注（「主线路加密，已切到备选」），而不是继续当判定依据。改之前先确认 `agedm` 那类「全加密」的源仍被判成 `declined` —— 否则就是把这一节的结论整个推翻。

## 二、15 个角色 → 前端字段

左边是模型里的角色名（也是 `web.fields` 的键），右边是转换后前端真正读的字段。前三列之后的所有行都由 `model.js` 填。

| # | 角色名 | 前端字段（转换后） | 谁来填 |
|---|---|---|---|
| 1 | `id` | `id` | `card()`，空串兜底 |
| 2 | `title` | `title` | `card()` |
| 3 | `cover` | `cover` | `card()`，`//` 补 `https:` |
| 4 | `score` | `score` | `card()`，缺省 `''`（不是 `0`，`0` 会被当成真值显示成「0 分」） |
| 5 | `tags` | `tags[]` | `card()`，非数组给 `[]` |
| 6 | `description` | `description` | `card()` / `detail()` |
| 7 | `category` | `category` | `card()` |
| 8 | `badge` | `badge` | `card()`，也是 `episodeLabel` 的原料 |
| 9 | `episodeCount` | `episodeCount` | `card()` 取 0；`detail()` 缺省用 `episodes.length` |
| 10 | `episodeLabel` | `episodeLabel` | 派生：「共 N 集」→ `badge` → `playAt` |
| 11 | `episodeNumber` | `episodes[].episodeNumber` | 由 `no` 转来 |
| 12 | `source` | `play.lines[].url` | `alts[].url` |
| 13 | `duration` | `duration` / `episodes[].duration` | 缺省空串 |
| 14 | `ref` | `episodes[].ref` + `episodes[].id` | **原样保留**，下一阶段 play 要用 |
| 15 | `playAt` | 只进 `episodeLabel` | 卡片角标的第二候选 |

完整的 16 个角色里剩下的 `code` / `slug` / `tagName` 走的是标签管线（`adaptTags`），spider ABI 还没有 `tags` 能力，这一轮不碰。

## 三、转换层为什么必须存在

因为 `web.paths` 想退役。今天一个源要能用，配置里得写 `paths.home = "https://…/api/home"`、`paths.detail = "…?id={id}"`，前端拿 `apiPathFor()` 拼 URL，再拿 `adaptVideo()` 把响应掰成卡片。这套东西全部建立在「内容是一个 HTTP 接口」这个假设上。

spider 打破的正是这个假设：`detail(ctx,{ref})` 里 ref 是站点自己的标识（`ep2026476948`、`ep1`、`zheng_pian`），不是 URL 片段。前端拼不出请求，也不需要拼——调用发生在 WebView 里，前端只拿结果。

于是一整条链路要重排：

```text
现在   配置(paths) → apiPathFor → Java 桥取 JSON → adaptVideo/adaptDetail → 卡片
阶段 2 配置(spider) → SpiderBridge 调 cap → spider 返回模型 → HGModel → 卡片
```

`HGModel` 就是右边这道箭头。它存在的价值不是「多个抽象层」，是**让 `app.js` 一行不改就能吃 spider 的返回**——`renderHome` 读 `item.episodeLabel`，`renderDetail` 读 `item.number`，这些读法都由 `model.js` 负责满足。哪天前端改成直接读 spider 模型（`episodes[].no`），`model.js` 就可以整层删掉，删的时候不改任何一个 spider。

字段缺失必须给空串/0 这条规矩也落在这里。模板里 `${undefined}` 会渲染成字面量 `undefined`，2026-10-18 那排选集格子就是这么来的——那次是 `episodeNumber` 没取到。转换层不给自己留「这个字段可能没有」的机会。

## 四、只为兼容保留的字段（下一阶段可删）

前端改读模型之后，这四个键没有存在理由：

| 字段 | 谁在读 | 删的条件 |
|---|---|---|
| `episodes[].number` | `renderDetail`：`data-episode="${item.number}"` | 改成读 `episodeNumber` |
| `episodes[].id` | 无人读 | 直接删；它只是 `ref` 的副本 |
| `paged.nextPage` | `adapters.js` 的列表调用点（判 `=== null`） | 列表页改读 `hasMore` |
| `play.source` | spider 自己给的（`resolveUrl` 读 `source \|\| url`） | 播放层统一读 `url` |

`episodeLabel` **不在**这个表里。它是给人看的文案（「共 3 集」），不是模型字段；等前端改读 `episodeCount` 自己拼句子时可以重新讨论，但它不是「兼容残留」，它是一条展示规则。

`episodeCount` 也不会删。`continueWatchingMarkup()` 拿它算「全剧已看完」，那个判断必须有总集数。
