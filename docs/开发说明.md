# AIIvideo

应用对外叫 **AIIvideo**，图标是白底黑 A。竖屏沉浸播放流、REST 数据层、WebView 原生 HLS 播放，以及真机上的冷启动与弱网优化。

结论看 [`docs/2026-10-15-橙子短剧改造-说明.md`](docs/2026-10-15-橙子短剧改造-说明.md)（改造本体）和 [`docs/2026-10-16-用户自带源与适配层.md`](docs/2026-10-16-用户自带源与适配层.md)（用户自带源、网络层、缓存）。README 只说明每个目录是什么、怎么复现常用动作。

包名仍是 `com.huangguo.mobile`——改包名等于换一个应用，覆盖安装会失败，所以没动，见文末「品牌」。

## 发版清单

```bash
cd work/shells
./build.sh release           # 刷补丁 → verify → 打包 → 报 sha256
cp cz-final.apk ../../AIIvideo-<版本>.apk
shasum -a 256 ../../AIIvideo-<版本>.apk
```

然后在 GitHub 建一个 Release，把 APK 传上去，Release notes 里贴 sha256。

**仓库里不放 APK。** 两个原因：二进制进了 git 历史就删不掉（每版 8MB）；
APK 里烧着账号服务器的实际地址和 appId，放 Releases 至少是个显式动作。

**没有 CI。** 构建需要原始样本 APK，而它不是这个仓库的东西。
押在 GitHub Actions 上只会得到一个每次必红的 workflow。

发版前对着打勾：

- [ ] `./build.sh verify` 通过（补丁集 == 工作树）
- [ ] 真机装上跑一遍：冷启动 / 换源 / 播放 / 收藏 / 观看历史
- [ ] 三条源各测一次：苹果CMS 站、AGE动漫、普通 REST 源
- [ ] 账号后端 `curl https://<你的域名>/api/healthz` 有响应
- [ ] 版本号有变（`AndroidManifest.xml` 的 versionCode / versionName）
- [ ] Release notes 里写了 sha256

## 重打包

改动集中在 [`work/shells/cz_repack/`](work/shells/cz_repack/)：前端资源在 `assets/`（`app.js`、`app.css`、`app.html`、`feed-player.js`），原生补丁在 `smali/`。

```bash
cd work/shells
./build.sh fast      # 从 cz_repack/ 直接打包（日常迭代）
```

改完工作树要同步补丁集，再验证它没漏东西：

```bash
./build.sh sync-patches   # 以「基准解包 vs 工作树」的文件级 diff 刷新 patches/
./build.sh verify         # 从原始样本重建，与工作树逐文件比对
```

`verify` 通过就说明 `chengzi-v0.3.15.apk` + `patches/` 能精确还原当前工作树——这条链是能对上账的：

```text
chengzi-v0.3.15.apk + patches/(22 个文件 + 76 条删除)  →  clean 树  ≡  cz_repack/
fast 与 clean 两条路径打出的 cz-mod.apk    →  逐条目 CRC32 完全一致
```

也可以完全绕开工作树：

```bash
./build.sh clean     # 解包原始样本 → 套补丁 → 打包，不碰 cz_repack/
```

`build.sh` 内置了三条闸门：`node --check` 过一遍所有 JS（语法错会让界面白屏，且只有装机才看得见）、`zipalign`、`apksigner verify`。设备在线时 `INSTALL=1 ./build.sh fast` 可以一步装好。

### 补丁集为什么不用 mtime 推导

`cp -p` 会把新文件的 mtime 伪装成解包时间。上一版按 mtime 找改动，漏掉了 `assets/vendor/hls.min.js`——它的 mtime 是解包那一分钟，看起来像原版的。文件级 diff 是唯一可信来源，所以 `sync-patches` 拿基准解包和完整工作树对。

## 注意事项

- 根目录 APK 与 [`work/shells/cz-final.apk`](work/shells/cz-final.apk) 是同一产物；打包以 `work/shells/` 为源头。
- 播放走 WebView `<video>` 原生 HLS。hls.js 的 XHR 会带 `Origin: https://appassets.androidplatform.net`，CDN 据此返回宣传片；`<video src>` 的媒体请求不带这个 Origin。**那条 hls.js 退路已经删掉**，连带把 CSP 的 `connect-src` 从 `https:` 收回 `'none'`、去掉三处 `blob:`（全应用无 `fetch` / `XMLHttpRequest` / `WebSocket`，网络一律走 Java 桥的 `HttpURLConnection`）。
- 站点入口走 Cloudflare，国内移动网络下时通时断（同一个接口实测 1.3s ~ 28s 都有）。图片和视频走国内节点所以一直流畅。这是当前体验的主要瓶颈。
- 站点域名会漂移，[`work/drama_api.py`](work/drama_api.py) 里有域名发现逻辑，可移植进 App。

### 对外更新通道：已全部切断（2026-10-16）

这个包原来挂着**两条**外部 GitHub 通道，现在两条都切了。

**一、热更新（站点规则 + 主题）**

```text
HotUpdateManager.INDEX
→ github.com/MrSsg/HuangguoAPP-HotUpdates/releases/latest/download/hot-update.json
```

切断前实测它是活的：CDP 读到 `window.HotRuntime` 是 `{"revision":16,"version":"2026.10.15.16"}`，`resources-r16.zip` 用包里 pin 的公钥验签通过。

**为什么切**：数据层换成一整套 `/api/` REST 之后，「站点规则」里真正还活着的只剩 `headers` 那两行。`selectors` / `patterns` / `routes` / `attributes` 只在 `SiteRepository` 抓 HTML 的分支里被调用，而那条路已经没有入口了（`selector` 被调 19 次、`route` 11 次，全在 `SiteRepository` 内部，它那 10 个公开方法对应的语义词现在全有 REST 路径）。`origin` 又在 `SiteProfile` 里钉死。也就是说这条通道最值钱的能力——域名漂移自愈——我们主动放弃了，剩下的收益撑不起一条对外信任链。

**怎么切的**（三处）：

| 位置 | 动作 |
|---|---|
| `HotUpdateManager.check(Z)` | 开头直接 `return status()`，一个网络请求都不发。整条 download → verifyEnvelope → requireCompatible → stage → prune 链路随之不可达 |
| `assets/hot-update-public.pem` | 换成一把新生成的 ECDSA 公钥。配对私钥留档在 `work/shells/.build/brandkey/`（`.build/` 被 gitignore，也不进 APK），**上游那把再也验不过**，所以这是「断开」而不是「暂停」 |
| `assets/hot-runtime.js` | 整个删除（主题应用器，theme 恒空；连带从 `app.html` 的 script 列表移除） |

**`HotUpdateManager.resource()` 不要动。** 名字叫「热更新资源」，但它其实是整个 `shouldInterceptRequest` 的处理体——`appassets.androidplatform.net` 底下所有东西都从它走，包括从 APK 内置 assets 取 `app.html`。把它 stub 成 `return null`，WebView 就会真去 DNS 解析那个虚拟域名，直接 `ERR_NAME_NOT_RESOLVED` 白屏。我踩过一次，注释留在 `check()` 里了。

**二、APK 自更新**

```text
UpdateManager.MANIFEST_URL
→ github.com/MrSsg/HuangguoAPP-for-Andriod/releases/latest/download/android-update.json
```

这个仓库**已经 404**，所以 App 里那个「检查更新」从来就没成功过，只是每次冷启动白打一次外网。切了四处：

| 位置 | 动作 |
|---|---|
| `UpdateManager.check(Z)` | 直接返回 `cached()`（纯本地读缓存），不发网络 |
| `UpdateManager.download(Progress)` | 直接返回 `null`，封掉 `download-update` 这个桥动作的口子 |
| 前端启动自检 | 去掉 `setTimeout(checkUpdate, 3000)` |
