# 去掉内置的黄果源 · 分类页加载态（2026-10-19 晚）

两件事：一是「黄果源不要内置」，二是「加载那个界面太单调」。

第一件事查下去有个结论要先说清楚：**黄果源没有接口可以迁移**，所以这不是迁移，是删除。

---

## 一、黄果源到底是什么

打开 `site-default.json` 看它的内容：

```
origin: ''        ← 空串
paths:  null
categories: null
web.api: 没有
```

它**没有任何内容地址**。剩下的只有三样：

1. `web.ui` 里一份界面默认值（tabs / categoryIds / categoryLabels /
   categoryTitles / categoryLeads / popularTags / tagGroups）
2. `ContentMode` 那套解锁流程（`enter-private` 密码 `ssgnb`、年龄确认）
3. 前端二十来处 `privateMode()` 分支

内容早就断了 —— 迁移到 spider 的前提是「有个接口可以包成 js」，这里没有。
所以能做的是把这三样一起删掉，把 App 变成真的壳。

---

## 二、删掉之后才发现的那个 bug

前端第一句就是 `contentSource = 'huangguo'`（硬编码），冷启动还会走一遍
`enter-private` + `confirm-private-age`，然后把 `contentSource` 锁成黄果。

后果不是「多了一个没用的源」，而是**用户装的任何源都被当成私密模式**：

| 位置 | 症状 |
|---|---|
| 分类页 | 套黄果模板：副标题「换脸与魔改，探索影像新可能。」+ 一个只有一个按钮的分区选择器 |
| 首页 | 「热门漫剧」当区块标题 |
| 标签页 | 按黄果的分组渲染 |
| 搜索页 | 结果下面挂一排「成人短剧 / 成人漫剧 / AI换脸 / AI魔改」 |

你截图里 3DCG 那页顶着「换脸与魔改」、下面一个孤零零的「3DCG」胶囊，就是这个。

**改法**：`contentReady` 不再进私密态，`contentSource` 固定 `hongguo`，
启动时顺手 `leave-private` 把 Java 侧的状态拉回公开。`privateMode()` 从此恒 false。

---

## 三、删了什么

| 文件 | 动作 |
|---|---|
| `site-default.json` | 删 `web.ui`、`web.categories`（7115 → 3894 字节） |
| `site-web.js` | 构建时重新生成（5254 → 2118 字节） |
| `tags.json` | 删（9578 字节，全项目零引用） |
| `app.js` | `contentSource` 不再锁黄果；`categoryLead / categoryTitle / categoryTabs` 的黄果默认文案删掉 |
| `app.js` | 搜索页那排硬编码胶囊（上一轮已经删） |

`site-default.json` 现在只留四样东西：`headers`（UA/Referer）、`doh`（DoH 服务器）、
`cover`（封面白名单）、`fields`（字段别名）。前三是「网络怎么走」，第四是「字段怎么对上」，
都是壳该管的。界面常量全部搬走 —— 它们本来就该跟着源。

副标题的处理是「没配就不显示」。一句对不上内容的副标题，比没有副标题更让人困惑。

## 四、加载态

分类页加载时原来是「已显示 0 部」+ 空网格 + 一行「正在加载…」，一屏全黑。

现在：6 张海报位的骨架卡（复用首页那套 shimmer 动画），右上角「正在加载…」，
底部重复的那行删掉（同一个词在一屏里出现两次）。

骨架卡是新加的 `.skeleton-card`：`aspect-ratio: 114/153` 跟真实海报同比例，
加载完不会跳高。首页那套 `skeleton-home` 自带横幅位，套到网格页会多出一块不属于
本页的大图，所以没有复用。

## 六、必须说清楚的一个副作用

`AppStore` 用 `ContentMode.active()` 决定本地数据目录：

```java
this.preferences = context.getSharedPreferences(
    "huangguo".equals(source) ? "huangguo-data" : "dual-data-hongguo", 0);
```

以前 active 是 `huangguo`，本地收藏 / 进度 / 历史存在 `huangguo-data`；现在恒
`hongguo`，读的是 `dual-data-hongguo`。**本地那三样会看起来「没了」**。

不是删了，是换了文件。判断：内容源换成 spider 之后，作品 id 体系已经不同，
旧记录对不上任何片子 —— 让它们继续显示反而更糟（点进去是「找不到」）。
账号同步（Parse）不受影响。

要真迁移的话是另一次改动：读旧文件、按 id 过滤、只留对得上的。

## 七、第二阶段：把 Java 侧那个类也删了

上一轮改完是「行为上不再进私密态」，代码里 `ContentMode` 还在。这一轮清干净。

**Java（少 1 个类、3 条命令、1 个死方法）**

| 位置 | 动作 |
|---|---|
| `ContentMode.java` | 删（108 行） |
| `MainActivity` | `enter-private` / `confirm-private-age` / `leave-private` 三条桥命令删；`content-status` 改成返回固定公开态 |
| `MainActivity` | `dispatch()` 里那段 `contentMode.require(source)` 删 —— 内容源只剩一个，没有「切了源旧请求要作废」这回事了（前端 `routeToken` 管同一条路） |
| `MainActivity` | `rebindContent()` 删：它原来是给私密态切换用的，换源走的是 `SourceConfig` 那边的 `Activity.recreate()` |
| `AppStore` | 不再按 source 分 `huangguo-data` / `dual-data-hongguo` 两个文件，固定后者 |
| `DualContentRepository` | 去掉 `mode` / `source` 两个字段和旧的 3 参构造 |

**前端（少 17 处判断、一个后门）**

- `privateMode()` 定义删除，17 处 `privateMode() ? A : B` 全部落成 B 那一侧
- 「连点版本号 5 次 → 输密码 → 过年龄门 → 进私密库」整套入口删了（密码 `ssgnb` 写死在
  前端这件事本身就该没）
- 分类页那根滚动收起的紧凑头废掉（它只有私密态会触发），`compactMarkup()` /
  `updateCompact()` 留成空实现，不动调用点

**顺手修好的两处**（都是同一个根：只在私密态渲染，别的源永远看不到）

- 首页「按类型浏览」那排：原来公开态读的是 `ui.publicPopularTags`，而所有源配置里它
  都是空数组 —— 于是首页只剩一个「全部类型」按钮。现在 `publicPopularTags` 空就退回
  `popularTags`，hanime1 首页立刻出现「中文字幕 / 巨乳 / JK / 純愛」。
- 分类页的子分类切换器：原来 `privateMode() ? <segmented> : ''`，于是苹果CMS 那种
  「一个 tab 挂四十多个分类」的源永远切不到第二个。现在改成 `tabs.length > 1` 才画。

## 八、还欠着的

- **`unlock-overlay` / `age-gate` 两块 DOM 还在 `app.html` 里**：没有任何打开路径了，
  恒 hidden。留着是因为返回键那几处还在读它们的 `hidden` 状态，删 DOM 要连带改逻辑。
- **`DualContentRepository` 这个名字**：现在只剩一条链路，「双」字是历史遗留。
  改它要动字段类型和几处构造，收益只是少两个字。
- **首页类型栏**：`ui.publicPopularTags` 是空的，首页只剩一个「全部类型」按钮，
  看起来有点空。要么源配置里补 popularTags，要么让前端拿标签前四个顶上。
