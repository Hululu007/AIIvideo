# 91porn 标签页：从「暂不支持 tag-list」到 10 个类型（2026-10-19）

真机上点首页的「91原创」标签，页面变成一句话：

```
加载失败
出了点小问题，重试一次；总不行就到设置里换个源。
这个 spider 源暂不支持「tag-list」（当前支持 首页 / 分类 / 搜索 / 详情 / 播放）
```

搜索框里是 `#91原创` —— 说明用户点的是类型卡，走的是 `tag-list` 动作。

---

## 一、断的是三层，不是一层

三处各自独立，缺哪一条都是同一个画面：

| 层 | 文件 | 原来 | 现在 |
|---|---|---|---|
| 前端分派 | `assets/app.js` | `SPIDER_MISSING` 里写死 `tags` / `tag-list`，`api()` 直接抛错，请求没出前端 | 只留 `recommend` / `newest`；`tags` / `tag-list` 有 cap 映射 |
| 模型转换 | `assets/model.js` | `fromBridge` 没有 `tags` 这个能力名 | 加 `tags()` + `TAG_CAPS` |
| 源实现 | `spiders/porn91.js` | 没有 `tags` / `tagList` 函数 | 从首页导航栏抠分类当标签 |

第三条最容易被忽略。detail 里那句 `tags: []` 是**站点的形状**（这部片确实没挂话题标签），
但「全部类型」页问的是**整站有哪些分类**，那是有的 —— Java 时代 1.0.30 就修过一次
（「全部类型 0 个标签」），迁成 spider 时按旧结论又丢了。

---

## 二、源这边怎么改

`/v.php` 的导航栏长这样：

```html
<li><A href="https://901.26702.app/v.php?category=ori&viewtype=basic">91原创</A></li>
<li><A href="https://901.26702.app/v.php?category=hot&viewtype=basic">当前最热</A></li>
...
<li><A href="https://901.26702.app/v.php?category=top&m=-1&viewtype=basic">每月最热</A></li>
```

11 条链接、10 个 code（`top` 出现两次，只是 `m` 参数不同），按 code 去重。

三个决定：

- **标签名用站点原文**，不钉表。实测 2026-10-19 站点自己改了叫法：
  `hot` 叫「当前最热」不是「热门」，`top` 叫「本月最热」不是「本周榜」，
  `rf` 叫「最近加精」不是「精选」。钉一张表等于把名字冻在某天的快照上。
- **文本不像分类名时退回 `CATEGORIES`**（空 / 超过 16 字 / 带标签残留）。站点按
  `Accept-Language` 分流，英文 UA 下导航是 `91` / `Hot` / `Top this Mon.`；
  宁可显示旧中文名，也不要在标签页上显示一句英文。
- **导航不足 3 条就当没抓到**，整体退回内置十个。站点改版时只剩一条「分类」链接，
  拿它渲染整页「全部类型」会显示「1 个标签」，比明确回退更糟。

`tagList` 不写新解析，直接复用 `category` —— 这个站的分类页和标签页是同一个页面，
`slug` 就是 category code。cap 名用 `tagList`（驼峰），因为宿主页 `__spiderRun`
是 `site[cap]` 直接取函数，带横杠的名字取不到。

顺带省了一次请求：`ensureGuest()` 那次 `/v.php` 的正文留了一份（`guestPage`），
`tags()` 直接用。不带游客标记时列表和导航都是对的，只有详情会随机换片。

## 四、前端那两处

`app.js`：

```js
const SPIDER_CAP = { home, category, search, detail, tags: 'tags', 'tag-list': 'tagList' };
const SPIDER_MISSING = new Set(['recommend', 'newest']);
```

`SPIDER_MISSING` 原来把 `tags` / `tag-list` 也列着，等于前端替所有源做了统一的
「不支持」判决。现在放开，由源自己决定 —— 没写的源会收到宿主页那句
`spider 没有实现 xxx`，`spiderErrorOf()` 把它翻成
`这个源没有实现「全部类型」（spider 里没有 tags 函数）`，比内部术语可读。

`model.js` 的 `tags()` 三条兜底：slug 缺失用 name 顶、name 缺失用 slug 顶、
group 缺失归 `other`。最后那条不是洁癖 —— `renderTags` 是
`tags.filter(tag => tag.group === id)`，group 一旦是 `undefined`，页面就是
「N 个标签」写在标题上、正文一片空。

## 六、怎么验

1. 装新 APK（前端 app.js / model.js 变了，旧的装上去还是那句「暂不支持」）。
2. 设置页贴 `https://149.104.21.177.sslip.io/market-spider.json`，勾 91porn 重装一次
   —— 重装会**重新下载 js**，覆盖 `files/spiders/porn91.js`。只切源不会更新源码。
3. 冷启动 → 首页点「全部类型」→ 应看到 10 个标签（91原创 / 当前最热 / 本月最热 /
   10分钟以上 / 20分钟以上 / 本月收藏 / 最近加精 / 高清 / 本月讨论 / 收藏最多）。
4. 点任一标签 → 24 条卡带封面，搜索框显示 `#<标签名>`，下滑能翻页。

判失败看 logcat：`[spider-api] tags → cap=tags` 有没有出现。没有就是前端没更新；
有但报错，看那句错误是 `没有实现`（源没更新）还是 `请求失败`（网络/镜像）。

## 六点五、真机验收（17:12，设备 23113RKC6C）

第一次装完仍然报同一句，根因不在代码：设备上那个 1.0.32 是 **15:57 装的旧包**
（`lastUpdateTime=2026-10-19 15:57:51`），构建时间早于这轮改动，前端还是旧黑名单；
同时 `files/spiders/porn91.js` 也是旧源码（`cap=tags` 那条根本没进去过）。

重装 APK + 用桥重装源之后，实测：

```
[spider-api] tags     → cap=tags     args={}                      ok ms=2071
[spider-api] tag-list → cap=tagList  args={"slug":"ori",...}       ok ms=3992
```

界面：全部类型页「10 个标签」、分组「分类」、十个按钮全是站点原文；
点「91原创」→「已显示 24 部作品」、搜索框 `#91原创`、封面正常、下滑翻页
24→48（nextPage=3）；详情 `829607946` 标题「视频验证」、封面在 CDN；
`play` 给 `state=ready`、`https://la.btc620.com/mp43/1253049.mp4?st=…&e=…&f=`。

一条操作上的教训：**装 APK 和装源是两件事**，两边都得更新。
只看「装的是 1.0.32」会以为前端已经新了 —— 版本号相同不代表内容相同。

## 七、还欠着什么

- **其它源没有 `tags`**：hanime1 / mrds66 / missav 都没实现这个 cap，现在点
  「全部类型」会看到「这个源没有实现「全部类型」」。比原来的统一黑名单准确，
  但仍然是一句报错。hanime1 的 detail 里有 `parseTags`，整站清单要另打一个页面；
  mrds66 有现成的 `/tag/` 页。下一轮按站补，不共用一套解析 —— 三家标签语义不一样。
- **91porn 的标签没有分组**：全归 `category`。站点就一排分类，没有层级，
  硬造分组只会多一层噪音。
