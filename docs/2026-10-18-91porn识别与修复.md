# 91porn：补上站点识别，修掉中文搜索

**日期**：2026-10-18
**站点**：`https://901.26702.app/`
**动的文件**：`Porn91Site.java`（补 probe / matchesUrl）、`Porn91Adapter.java`（percentDecode 改按 UTF-8 解）

---

## 一、原来缺的是「认站」

`Porn91Adapter` 835 行的解析一直都在，但 `Porn91Site` 只实现了 `/api/` 分流 —— **没有 probe**。
后果是用户把站点地址填进「设置源」根本加不进来：`load()` 会先 fetch 一次，拿到 42KB 的
HTML，然后报「返回的不是合法 JSON」。

补上之后：域名（901.26702.app / 91porn.com）+ 指纹（`/v.php` 里有 video-title 卡片、
至少 5 条 `view_video.php?viewkey=`）两道都能过。

配置里三样东西是现抓的，不能写死：

- **分类表**：站点导航栏里就十个 code（ori / hot / top / hd / rf / tf / long / longer / md / mf）。
  不认识的 code 站点回的是「全站最新」而不是 404 —— 所以只能写实测过的。
- **封面白名单**：封面在 CDN 上（实测 `1729130453.rsc.cdn77.org`），漏了就全是灰底。
  从首页 HTML 的 `src/poster/data-original` 里现抓，顺手把统计域名剔掉。
- **底部导航**：十个分类折成 5 + 更多。

## 二、中文搜索一直是 0 条

`percentDecode()` 老实现是逐字节 `(char) byte` 拼字符串：

```java
sb.append((char) ((hi << 4) | lo));   // 中文变成 Latin-1 乱码
```

对 ASCII 没问题，对中文就是把一个 UTF-8 字符的三个字节拆成三个字符（"自" → "è‡ª"）。
这个乱码串再被 `enc()` 编码回去，就是另一串字节，站点按那串搜 —— **0 条，且不报错**。

症状很有迷惑性：首页、详情、播放全正常，只有搜索永远空。因为只有搜索会把 URL 里的
中文参数解码一次再编码回去。

现在按字节收、按 UTF-8 解，往返用例 `编码解码往返` 钉住了。

## 四、播放那一段的坑

播放地址长这样：

```text
https://ccm.91p52.com/358999.mp4?st=<签名>&f=<token>
```

两个麻烦：

1. **证书链不完整。** `openssl s_client` 看得到 `* .91p52.com` 和 Let's Encrypt YE2，
   但 `Verify return code: 20 (unable to get local issuer certificate)` —— 服务器没发
   中间证书。浏览器能靠缓存/AIA 补，VLC 这类库不一定。表现是**加载圈一直转**，
   过一阵可能自己开始播。
2. **VLC 不走 App 的代理。** 页面本身是 `AiiHttp` 拉的（走代理），播放是 libVLC 自己
   建连接。规则一样：直连大概率被墙。

所以这个源「能不能播」取决于手机当下的网络能不能到 `ccm.91p52.com` —— 和页面能不能
打开是两件事。真机上实测能播，但首帧慢。
