# AGE动漫 逆向

**日期**：2026-10-16
**目标**：`https://www.agedm.io/`（PC）、`https://m.agedm.io/`（移动）
**产出**：`work/shells/agedm.json` —— 适配器参数，不是当前 APK 能直接吃的配置
**结论**：**元数据全通；配置层面堵在路径前缀上；播放层拿不到直链。**
**真机测试**：`149.104.21.177:/srv/cfg/` 上的两份配置 + 设备 `7f8f5254` 实测，结果在第七节。

---

## 一、先把结论摆出来

| 层 | 状态 | 依据 |
|---|---|---|
| 首页 / 目录 / 搜索 / 详情 | ✅ 干净 JSON，无鉴权 | `api.agedm.io/v2/*` 裸 curl 200，无 Cookie 无 Referer |
| 手机能不能连上 | ✅ 通 | 探针配置触发真请求，agedm 自己回了 403（`cf-ray` 带回来了），不是超时 |
| 直接写配置 | ❌ 堵死 | `paths` 必须以 `/api/` 开头（Java 硬编码），而它的接口在 `/v2/` |
| 播放地址 | ❌ 拿不到直链 | 三道锁：`jsjiami.com.v6` 混淆 JS + Go/WASM（307 KB）+ 签名头 |
| 播放绕路 | ✅ 可行 | 它的播放源就是苹果CMS 的采集站代号，同名作品在我们已有的源上能拿到明文 m3u8 |
| 要跑起来 | 需要一个适配器 | 和苹果CMS 同一个模式，见第六节 |

## 二、站点结构

两个入口，两套完全不同的实现：

```text
www.agedm.io    Go 模板服务端渲染（HTML 里能看到 [[each $data.comments]]）
                没有 XHR，没有 JSON，页面就是数据
m.agedm.io      Vue 2 + vue-router + vuex + axios 的 hash SPA
                baseURL = https://api.agedm.io/v2/
```

**数据在移动站那边。** PC 站只能爬 HTML —— 而那条路我们上一轮已经整块删掉了（`SiteRepository` 少 3055 行）。所以能用的只有 `api.agedm.io`。

PC 站上唯一一个 JSON 接口是评论：`/api/comment/{id}?page=1`，移动站那份在 `/v2/comment/{id}/?page=1`，两边数据一样。

### 接口是裸的

```bash
curl -s -H 'User-Agent: Dalvik/2.1.0' https://api.agedm.io/v2/home-list | head -c 80
```

```text
  200 application/json 22743  /v2/home-list
  200 application/json 3234   /v2/catalog?...
  200 application/json 2548   /v2/search?query=...
  200 application/json 7127   /v2/detail/20260286
```

**没有 Cookie、没有 Referer 校验、没有 UA 白名单。** 换 `Dalvik/2.1.0` 照样 200。这一点很重要：意味着适配器在手机上不需要任何浏览器上下文。

## 三、数据层 API

基址 `https://api.agedm.io/v2/`。

### `GET /v2/home-list` —— 首页

```text
键：latest(12) · recommend(12) · week_list
latest 元素：{AID, Href, NewTitle, PicSmall, Title}
```

`week_list` 是按星期分组的更新表（`{"0": [{id, name, mtime, namefornew, isnew, wd}]}`），按时区排节目单用的，首页用不上。

**注意这套字段名和后面几套都不一样** —— PascalCase，`AID` / `PicSmall` / `NewTitle`。

### `GET /v2/catalog` —— 目录

```text
/v2/catalog?genre=all&label=all&letter=all&year=all&season=all
           &status=all&resource=all&region=all&order=time&page=1&size=24
```

**参数名有坑，两个：**

| 参数 | 界面上的名字 | 真实含义 | 值 |
|---|---|---|---|
| `genre` | 版本 | **不是类型** | `all` / `TV` / `剧场版` / `OVA` |
| `label` | 类型 | 真正的类型 | 46 个中文词，`all` + 搞笑/运动/热血/战斗/… |
| `region` | 地区 | | `all` / `日本` / `中国` / `欧美` |
| `letter` | 首字母 | | `all` / A-Z |
| `year` | 年份 | | `all` / 2026…2000 |
| `season` | 季度 | **纯数字** | `all` / 1 / 4 / 7 / 10（桌面站显示「1月」，接口收的是 `1`） |
| `status` | 状态 | | `all` / 连载 / 完结 / 未播放 |
| `resource` | 资源 | 匹配是**松的**，大小写还不一致 | `all` / `BDRIP` / `AGERIP`，见下面的坑 |
| `order` | 排序 | | `time` / `name` / `hits` |
| `page` `size` | | | `size` 最大 100，实测 100 条正常返回 |

**值全是中文原文，不是代码：**

```text
region=日本      → total=4772      ✅
region=jp        → total=5666      ❌ 静默返回全站
genre=搞笑       → total=0         ❌ 搞笑的应该是 label=
label=搞笑       → total=1455      ✅
genre=TV         → total=3584      ✅
```

`label=搞笑` 返回 0 的时候很容易以为类型没数据 —— 实际是参数名选错了。

`resource` 的匹配规则很随意，实测一圈：

```text
resource=all      → 5666
resource=''       → 5666      空值等于 all
resource=BDRIP    → 606
resource=bdrip    → 606       小写也认
resource=AGERIP   → 169
resource=agerip   → 0         ← 同一个词，小写就不认了
resource=AGE-RIP  → 169       带连字符一样命中
resource=AGE      → 169       前缀也行
resource=RIP      → 633       不是 169+606，说明存的是另一种字符串
resource=xxx      → 0
```

像是 `LIKE '%值%'` 之类的松匹配，而且大小写敏感度不一致（`bdrip` 通、`agerip` 不通）。**配置里就用它自己字典给的那两个值**（`BDRIP` / `AGERIP`），不要自己变形。

响应：

```json
{ "total": 5666, "videos": [ ... ] }
```

`total` 是**数字**。元素字段：

```json
{
  "id": 20260286, "name": "冰剑的魔术师将要统一世界 第二季", "uptodate": "第2集",
  "time": 1792084362, "status": "连载", "play_time": "00:28", "type": "TV",
  "name_original": "冰剣の魔術師が世界を統べるⅡ", "name_other": "...",
  "premiere": "2026-10-08", "writer": "御子柴奈奈",
  "tags": "校园 魔法 奇幻", "tags_arr": ["校园", "魔法", "奇幻"],
  "company": "ZERO-G", "intro": "...",
  "cover": "https://gimg1.baidu.com/gimg/…src=https%3A%2F%2Fcdn.aqdstatic.com%3A966%2Fage%2Fcovers%2F20260286.jpg"
}
```

`cover` 是**百度图床的代理地址**，真图在 `cdn.aqdstatic.com:966/age/covers/{id}.jpg`。

### `GET /v2/search` —— 搜索

```text
/v2/search?query={关键词}&page=1
```

参数名是 `query`。`wd` / `keyword` 都返回 `{"code":40050,"message":"参数错误！"}`。

响应多包一层 `data`：

```json
{ "code": 200, "message": "",
  "data": { "videos": [...], "total": 2, "totalPage": 1, "conditions": {"page":"1","query":"冰剑"} } }
```

**字段名又不一致**：这里的类型数组叫 `tagsArr`，目录那边叫 `tags_arr`。同一个字段两种拼法。

### `GET /v2/detail/{id}` —— 详情

```json
{
  "video": {
    "id": 20260286, "name": "...", "name_other": "...", "name_original": "...",
    "company": "ZERO-G", "type": "TV", "writer": "御子柴奈奈",
    "plot": "校园 魔法 奇幻", "plot_arr": ["校园","魔法","奇幻"],
    "area": "日本", "year": 2026, "season": 10, "premiere": "2026-10-08",
    "status": "连载", "uptodate": "00:28 第2集",
    "intro": "...", "intro_html": "...", "intro_clean": "...",
    "star": 0, "rank_cnt": "1.41w", "collect_cnt": "275", "comment_cnt": "29",
    "comments_status": 1,
    "net_disk": null, "resource": "", "cpraid": "...",
    "cover": "https://gimg1.baidu.com/gimg/…src=…cdn.aqdstatic.com%3A966%2Fage%2Fcovers%2F20260286.jpg",
    "playlists": { "xigua": [["第01集", "age_..."], ["第02集", "age_..."]], "ffm3u8": [...], ... }
  },
  "series":  [...],
  "similar": [...],
  "player_label_arr": { "xigua": "西瓜", "bfzym3u8": "暴风", ... },
  "player_vip": "qq,youku,mgtv,qiyi,tt,iqiyi,baba,qiqi,panda,sohu,letv,pptv,xigua,wy,migutv,bilibili,appvip,zjm3u8",
  "player_jx": { "vip": "https://jx.wuzhoupai.com:8443/vip/?url=", "zj": "https://jx.wuzhoupai.com:8443/m3u8/?url=" }

```

`video` 一共 **37** 个字段。**没有 `episodes` 数组** —— 剧集在 `playlists` 里，按源分。

几个容易写错的地方：

- `cover` 也是**百度图床的代理地址**，真图同样在 `cdn.aqdstatic.com:966/age/covers/{id}.jpg`
- `uptodate` 和目录那边**不一样**：这里带播放时长前缀（`"00:28 第2集"`），目录里是干净的 `"第2集"`
- `rank_cnt` / `collect_cnt` / `comment_cnt` 都是**字符串**，`"1.41w"` 这种带单位的
- `year` / `season` 是**数字**（`2026` / `10`），不是字符串 —— 和 URL 参数里的 `"2026"` / `"10"` 形式不同

### `GET /v2/slipic` —— 轮播图

```json
[{ "AID": 20260158, "Title": "...", "PicUrl": "https://gimg0.baidu.com/gimg/…large%2Fageslides%2F20260158.jpg" }]
```

### `GET /v2/comment/{id}/?page=1` —— 评论

```json
{ "code": 200, "data": { "pagination": { "total": 29, "totalPage": 3, "curPage": 1, "pageCount": 10, "pageNoList": [1,2,3] }, "comments": [...] } }
```

### 不存在的

盲试过一圈，**全部返回 `text/html`**（站点的 SPA 兜底页），不是 404 也不是 403：

```text
/api/video/  /api/detail/  /api/anime/  /api/play/  /api/list  /api/search
/api/home  /api/catalog  /api/bangumi  /api/vod  /api/rank  /api/update
/v2/       /v2/api  /v2/video/  /v2/search  /v2/list  /v2/play/  /v2/playlist/
```

判断一个端点存不存在，看 `content-type`，不能看状态码 —— **永远是 200**。

`/v2/` 下确有其事的是 `/v2/captcha`（验证码 PNG，登录注册用）。PC 站那边对应 `/v2/captcha`，说明 `/v2/` 是后端真实前缀。

## 四、播放层：三道锁

这是唯一拿不到的东西。

### 链路

```text
1. GET /v2/detail/{id}
   → playlists[xigua] = [["第01集", "age_5ccekjDUyl1o7xBX%2Fcpg2ouNASaAPKruV…"], …]
                        ^^^^^^^ 加密的，不是 URL

2. GET xcdn.khfed.com:8443/jx/20230723ver/Play/global.min.js?v=20260512
   GET xcdn.khfed.com:8443/jx/20230723ver/Play/play.min.js?v=20260512
   GET xcdn.khfed.com:8443/jx/20230723ver/Play/jx.wuzhoupai.com.wasm?v=20260512

3. POST https://jx.wuzhoupai.com:8443/vip/Api.php
   Headers:
     video-parse-sign:    <600 字符十六进制>
     video-parse-time:    1792118275
     video-parse-uuid:    C0DFF160-B2A1-4F7D-A7C1-1BAFBDF14D10
     video-parse-version: V3.2
   Body: Params=<455 字符十六进制>
   → {"Status":1,"Appkey":"4f21112b7a18ea65123f34d4b2e22f60","Version":"V3.2","Code":10,"Data":"B7E61F40…"}
                                                       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 还要再解一次

4. 解出来才是 m3u8
```

### 三道锁分别是什么

**① `play.min.js` 是 `jsjiami.com.v6` 混淆的。**

```text
var iｉl='jsjiami.com.v6',iｉl_=function(){return['‮iｉl'],i1l1i=[iｉl,'MCd8w78cWBs=','w4bCiMKFw4A=',…]
```

（注意 `iｉl` 里混了一个全角 `ｉ`，是它故意的反调试。）字符串全在加密数组里，48 KB 的代码里一个明文 URL 都搜不到。

**② `jx.wuzhoupai.com.wasm` 是 Go 编译的，307 063 字节。**

```text
wasi_snapshot_preview1 · syscall/js.valueGet · syscall/js.valuePrepareString
go_scheduler · _start · resume · crypto/cipher: invalid buffer overlap
```

是 Go 的 WASM 运行时 + `crypto/cipher`。签名和对称加密都在这里面。

**③ 密文每次都变，缓存不了。**

同一集连拉两次：

```text
第 1 次  age_72feC…
第 2 次  age_5ccekjDUyl1o7xBX…
```

`sameCipherText: false`。所以没法「解一次存起来」—— 每次播放都得重新走一遍 WASM。

### 试过的两条近路，都不通

```text
GET https://jx.wuzhoupai.com:8443/m3u8/?url=age_xxx    → 200 text/html 6382 字节 《云播放器》
GET https://jx.wuzhoupai.com:8443/vip/?url=age_xxx     → 200 text/html 5067 字节 《云播放器》
```

两个「播放器页」里**一个 m3u8 都没有**，解密仍然发生在页面里加载的那个 WASM 里。想拿直链只能自己跑 WASM。

`video.net_disk`（网盘字段）实测是 `null`，这条路也没有。

### 要啃下来得做什么

1. 反混淆 `jsjiami.com.v6`（字符串数组 + 控制流平坦化），取出 CryptoJS 的密钥
2. 复现 `video-parse-sign` 的算法（600 字符，输入应该是 uuid + time + 密文）
3. 把 307 KB 的 Go WASM 移植成 Java —— 或者塞一个 WASM 运行时进 APK

`Version: V3.2` 和 `?v=20260512` 说明这套东西还在迭代，做出来也得跟着修。

**判断：不值得。** 这不是「花两天能做出来」的量级，而且是对抗性维护。

## 五、绕路：从同名采集源拿明文

**关键发现**：`playlists` 的 key 就是**苹果CMS 的采集站代号**。

```text
bfzym3u8  = 暴风    我们已经在用 bfzyapi.com
lzm3u8    = 量子    我们已经在用 cj.lziapi.com
ffm3u8    = 非凡
wjm3u8    = 无尽
xigua     = 西瓜（抖音 CDN）
```

也就是说 **AGE动漫 自己也是从这些采集站聚合的**，只是给地址套了层加密。

实测同一部作品（冰剑的魔术师将要统一世界 第二季）：

```text
bfzyapi.com?ac=detail&wd=冰剑的魔术师将要统一世界
  → 命中 2 条
    - 冰剑的魔术师将要统一世界 | 日韩动漫 | 第01集$https://c1.rrcdnbf2.com/video/…/index.m3u8
    - 冰剑的魔术师将要统一世界 第二季 | 日韩动漫 | 第1集$https://fengbao13.com/video/…/index.m3u8

cj.lziapi.com?ac=detail&wd=冰剑的魔术师将要统一世界
  → 命中 3 条，其中「冰剑的魔术师将要统一世界第二季」
    → https://v.lzcdn31.com/20261009/12483_0e19a5e2/index.m3u8
```

**明文 m3u8，直接能播。** 没有加密、没有签名、没有 WASM。

> 注意这条绕路解决的是**播放**，不是上面那个路径问题 —— 元数据那几层还是需要适配器。

所以一条可行路线是：**元数据用 agedm（它的分类体系比 CMS 好得多），播放时拿标题去同名采集源里搜，命中就播。** 代价是：
- 要多打一次别的源的接口
- 靠标题匹配，会有对不上的（AGE 的命名和采集站不完全一致，比如「第二季」vs「第二季」的空格差异）
- 集数对不齐时要能容忍

## 六、写配置时对不上的四处

按我们现有的 schema 逐条对：

### 1. `web.categories` 要数字，agedm 全是命名值

```java
// UserSource.validate()
if (categories.optInt(slug, 0) <= 0) return "web.categories['" + slug + "'] 不是正整数 cate_id";
```

agedm 的筛选维度是 `region=日本&label=搞笑&genre=TV`，**没有任何数字 id**。这一条就会把配置直接拒掉。

要么放宽校验（允许字符串 cate_id），要么把 `{cateId}` 换成一组具名占位符（`{region}` `{label}` `{genre}` …）。

### 2. ~~路径必须以 `/api/` 开头~~ —— **已修**（2026-10-16 当天）

测试时发现的：`SiteRepository.detail()` 里硬编码了一句「路径不是 `/api/` 开头就抛异常」，
所以 `origin` 指向 `api.agedm.io` 也没用，路径还是得叫 `/api/...`，而 agedm 只有 `/v2/...`。

**已经改成支持 https 绝对地址了**：

```text
origin = ""  +  paths.home = "https://api.agedm.io/v2/home-list"   → 原样使用 ✅
```

现在的 `paths` 每条要么是 `/` 开头的相对路径（拼 `origin`），要么是完整 https 地址（不看 origin）。
详见 `docs/站点配置参考.md` 的 `web.paths` 一节。

**所以这一条不再是拦路虎** —— 剩下的是第 3 条（形状）和第 4 条（播放）。

### 3. 响应形状对不上，别名机制救不了

`fields` 只能改标量字段的名字，改不了结构：

| 我们要的 | agedm 给的 |
|---|---|
| `home.featured` / `latest` / `cate_rec` | `{latest, recommend, week_list}` |
| `list.items` + `pagination{page,pages}` | `{total, videos}` / `{code,data:{videos,total,totalPage}}` |
| `detail.episodes[]` | `video.playlists{源: [[集名, 地址]]}` |
| `tags.categories[{code,tags}]` | 没有这个接口，得从筛选项字典合成 |

而且字段命名有三套（PascalCase 首页 / snake_case 目录 / 又一种 snake 搜索），`tags_arr` vs `tagsArr` 这种还得一字段一别名。

### 4. 播放拿不到

见第四节。

**结论**：**这个站点需要的是一个适配器（`adapter: "agedm"`），不是一份配置。** 和苹果CMS 那条线是同一个模式 —— `AgedmAdapter.java` 负责把 `/v2/*` 的形状翻成我们的形状，前端一行不用改。

`work/shells/agedm.json` 是按这个前提写的**适配器参数**：路径、筛选维度字典、导航分组的预设、字段别名、播放源标签表。校验（`validate()`）现在会拒掉它，因为第 1 条那个数字 cate_id 约束。

## 七、真机测试结果

把探针配置和正式配置都传到测试机（`149.104.21.177` 的 Caddy，`/srv/cfg/`），用设备 `7f8f5254` 上的 App 实测。

### 手机能连上 api.agedm.io

探针配置把 `origin` 设成 `https://api.agedm.io`，加进去之后 App 立刻发了真请求：

```text
[http] GET api.agedm.io/api/home
[http] 走代理 SOCKS 64.64.224.121/<unresolved>:19108（带认证）
[http] 预热失败（前端会照常发真请求）：IOException HTTP 403 @ https://api.agedm.io/api/home
```

**403 是 agedm 自己 nginx 回的，不是超时也不是 DNS 失败：**

```bash
$ curl -sI https://api.agedm.io/api/home | grep -iE 'server|cf-ray'
server: cloudflare
cf-ray: a4b3bc768afd2ae9-LAX
```

所以**链路没问题**，这条路走得通 —— 卡住的是路径形状，不是可达性。（换源时还强制走了 SOCKS 代理，也证明代理那条线对 agedm 有效。）

### 配置被拒在第一关

`agedm.json` 提交上去，返回：

```text
被拒：缺少 origin（站点入口地址）
```

原因：`validate()` 里只对 `adapter == "cms"` 放行，别的 adapter 值掉进 REST 分支，第一件事就是查 `origin`。

### 顺带测出来的两件事（写进配置参考了）

1. **`paths.*` 必须以 `/api/` 开头** —— 硬编码在 `SiteRepository.detail()`。写成 `/v2/home-list` 会走到那句抛异常，报出来的却是「detail 已改为纯 REST，抓 HTML 的分支已移除」，**提示词和真实原因完全无关**。
2. **`origin` 唯一的用途是拼在 `paths` 前面**。留空则路径原样交给适配器 —— 苹果CMS 就是靠这个工作的（它的 `origin` 是空的）。

这两条之前的配置文档里都没写清，是这次测试才挖出来的。

## 八、适配器写完了（2026-10-16 收尾）

这一节是事后补的，把「哪些做成了、哪些没有」落定。

### 写之前的实测：这站其实一半能纯配置接

用新加的 `web.shapes`（响应形状映射）+ `web.fields`（带点的字段路径），**零代码**跑通了：

```text
首页 /v2/home-list      → shapes.home: {featured: recommend, latest: latest}   ✅ 12 条
列表 /v2/catalog        → shapes.list: {items: videos, pages: {div: [total, $pageSize]}}  ✅ 翻页正常
封面                    → 百度图床代理，白名单五个 gimg*.baidu.com            ✅ 24/29 上屏
```

`envelope: ""` 是关键那一行 —— 这站的接口是**裸的**，没有 `data` 信封，而我们的 `fetchApi` 默认要求有。

### 卡在第 ⑥ 层：详情

```text
站点给   video.playlists = { "xigua": [["第01集","age_…"], …], "ffm3u8": [ … ] }
我们要   episodes = [{ ep_num, title, duration }, …]
```

「按位置把 `[[名,地址]]` 拆成对象」= **结构重排**，需要遍历 + 按位置访问。声明层能表达「取值、改名、路径、映射、一个除法」，表达不了这个 —— 差别不在难不难，在于它是程序。

所以写了 `AgedmAdapter.java`（约 400 行，含注释），和 `CmsAdapter` 同一套模式。

### 播放：绕过去了，而且能用

站点自己那条路是死的（`age_` 密文 + Go/WASM 签名门，见第四节）。但**它那 5 个播放源的代号就是苹果CMS 采集站**，同名作品在那些站上是明文 m3u8。

所以配置里加一个 `playback` 指向采集站，播放时拿标题去搜：

```text
[agedm] 播放匹配到采集站：冰剑的魔术师将要统一世界 第二季 第 1 集
video src: https://fengbao13.com/video/…/index.m3u8
video: readyState=4  t=12.5s  错误=无        ← 真机实测在播
```

**匹配要求标题完全一致**（去掉所有空白后比较 —— 这站的命名差异基本只有空格）。宁可报「没找到」也不猜：模糊匹配能提高命中率，但**匹配错了就是放错片子**，而且用户根本看不出来。

### 一个真机上踩到的坑（值得记）

`toVideos()` 第一版只按**目录**那套字段名写（`id/name/cover`），首页全是 `null`。原因是**同一个站两个接口两套命名**：

```text
/v2/home-list   { AID, Title, PicSmall, NewTitle, Href }        ← PascalCase
/v2/catalog     { id, name, cover, uptodate, tags_arr, … }      ← snake_case
```

改成「候选键列表取第一个有值的」就好了 —— 和前端 `fields` 别名是同一个套路，只是发生在 Java 那一侧。

第二个坑：`/v2/search` **只有它带 `data` 信封**，另外几个是裸的。同一个站内部都不统一，只能单独拆一次。
