## 二、宿主页暴露的东西（全局只有这两个）

```js
window.__spider          // 见下，唯一的能力入口
window.__spiderSite      // 初始为 null；spider 文件执行完必须给它赋值
```

`window.__spider` 的形状：

```js
window.__spider = {
  call(op, args) { /* args 传对象；返回**已解析**的对象 */ }
};
```

`op` 取值：`'net' | 'log' | 'done'`（阶段 0 只要这三个）。

**编码只有一层。** 契约早期版本里 §3 的驱动脚本写的是
`__spider.call('done', JSON.stringify(r))`，而 `call` 内部也会 `JSON.stringify(args)`
—— 于是 `done` 到 Java 那边是**字符串字面量**，得 parse 两次才解得开。
现在统一成：**调用方传对象，`call` 负责序列化一次**。宿主页对「传进来的已经是
字符串」也做了兼容（直传、不二次编码），但那是防御，不是接口。

**注意 `call` 返回给页面的是对象、给 Java 的是字符串** —— Android 的
`@JavascriptInterface` 只能同步返回基本类型/String，返回对象在旧 WebView 上是
代理对象，序列化行为不一致。所以宿主页负责 `JSON.parse`：

```js
window.__spider = {
  call(op, args) {
    const raw = window.__hgSpider.call(String(op), JSON.stringify(args || {}));
    try { return JSON.parse(raw); } catch (e) { return { ok: false, error: 'bridge 返回的不是 JSON' }; }
  }
};
```

`window.__spiderRun` 由宿主页实现（不是 spider 实现）：

```js
window.__spiderRun = function (cap, argsJson) {
  return Promise.resolve()
    .then(() => {
      const site = window.__spiderSite;
      if (!site) throw new Error('spider 没有导出 __spiderSite');
      const fn = site[cap];
      if (typeof fn !== 'function') throw new Error('spider 没有实现 ' + cap);
      return fn(window.__spider, JSON.parse(argsJson || '{}'));
    })
    .then(payload => ({ ok: true, payload }))
    .catch(error => ({ ok: false, error: String((error && error.message) || error) }));
};
```

## 三、Java 侧接口（runtime 必须照这个签）

```java
/** 阶段 0 的 ABI 号。壳把它和 spider 的 requires 比对。 */
final class SpiderRuntime {
    static final int ABI = 1;

    /** 把一个 spider 源码字符串装进宿主页并调用一次能力。**后台线程调用。** */
    static JSONObject call(Context ctx, String spiderSource, String cap,
                           JSONObject args, int timeoutMs) throws Exception;

    /** 释放宿主。MainActivity.onDestroy 必须调，漏了渲染进程常驻。 */
    static void shutdown();
}
```

返回值约定：

- 成功：spider 返回的 payload 原样（`JSONObject`）。阶段 0 里 `home` 的 payload 是
  `{"items":[...]}`。
- 失败：抛 `Exception`，message 就是给用户/日志看的那一句（`"spider 超时（15s）"`、
  `"spider 没有实现 home"`、`"net 拒绝：主机不在白名单"`）。

`SpiderBridge` 的签名（runtime 写）：

```java
final class SpiderBridge {
    @android.webkit.JavascriptInterface
    public String call(String op, String argsJson);   // 返回 JSON 字符串
}
```

### op 契约

| op | 入参 | 返回 |
|---|---|---|
| `net` | `{url, method, headers, body, charset}` | `{ok:true, status, body}` / `{ok:false, error}` |
| `log` | `{msg}` | `{ok:true}` |
| `done` | `{ok, payload}` 或 `{ok:false, error}` | `{ok:true}`，并**释放**调用方的闩锁 |

`done` 的两种边界情况，明确一下：payload 是 `undefined`（spider 的能力函数没写
`return`）按**成功**处理，payload 归一成 `null`；`error` 为空串按失败处理。宿主页
已经这么做了，runtime 不要另加判断。

### `net` 的三条现实约束（实现后补记）

1. **`status` 报不出 4xx/5xx。** `AiiHttp.getRaw/postFormRaw` 对非 2xx 直接抛
   `IOException("HTTP 404 @ url")`，不交 Response。所以成功必然是 2xx、`status`
   写死 200；失败走 `{ok:false, error:"HTTP 404 @ …"}`，没有 status 字段。
   要拿到真状态得给 AiiHttp 加带 Response 的入口，那是改公开面，阶段 0 不做。
2. **POST 的 `Content-Type` 带不上 charset。** `AiiHttp.postFormRaw` 里 MediaType
   写死 UTF-8，而 OkHttp 的 `BridgeInterceptor` 会用 body 的 MediaType 覆盖同名头，
   外面塞不进去。替代做法是「让字节对」：非 ASCII 按目标 charset 转成 `%XX` 再发，
   老服务器按自己的默认编码解表单，能收到对的中文。**局限**：严格按请求头 charset
   解表单的站仍会解错 —— 要修只能动 `AiiHttp`。
3. **payload 只收 JSON 对象。** `SpiderRuntime.call` 返回 `JSONObject`；spider 的
   能力函数返回数组时直接报 `"spider 返回的 payload 不是 JSON 对象（阶段 0 只收对象）"`，
   不静默包成 `{items:…}`。

`done` 是这个设计里唯一的终点：一次能力调用只允许一个返回值。spider 返回之后再
偷偷发请求的，直接丢弃（`SpiderBridge` 记一笔日志）。

### 宿主页怎么被驱动

`SpiderRuntime.call` 内部（顺序是硬要求）：

1. 主线程：拿 WebView（没有就建），`loadUrl(宿主页)`。
2. `onPageFinished` → 注入 spider 源码：`evaluateJavascript(spiderSource, null)`。
3. 再注入一次驱动，**能力名要拼进去，不能写死**：

   ```java
   String driver = "__spiderRun(" + JSONObject.quote(cap) + ","
           + JSONObject.quote(args == null ? "{}" : args.toString()) + ")"
           + ".then(function(r){__spider.call('done', r)})";
   ```

   两个细节：`cap` 和 `args` 都用 `JSONObject.quote` 转义（能力名将来可能带引号）；
   `done` 收到的是**对象** `r`，不是它的字符串形式（见 §2「编码只有一层」）。
4. `done` 回来 → 闩锁释放 → 后台线程拿到结果。
5. 看门狗：`timeoutMs` 到点还没 `done` → 销毁 WebView、抛 `"spider 超时（{n}s）"`。

## 四、spider 文件怎么写（host 的示例照着这个）

```js
__spiderSite = {
  id: 'dev-hello',
  name: '自检源',
  version: 1,
  requires: '>=1',
  hosts: [],                       // 阶段 0 不用网络

  async home(ctx) {
    ctx.call('log', { msg: 'hello from spider' });
    return {
      items: [
        { id: 'a', title: '卡片 A', cover: '' },
        { id: 'b', title: '卡片 B', cover: '' },
        { id: 'c', title: '卡片 C', cover: '' }
      ]
    };
  }
};
```

**赋值给 `__spiderSite`（不是 `window.__spiderSite =`，也不是 `module.exports`）。**
宿主页里它是 `var __spiderSite = null;`，非严格模式下直接赋值就是给全局。

## 七、共同的约定

- 所有跨线程状态收在 `SpiderRuntime` 里，`SpiderBridge` 只做协议转换，**不持状态**。
- 日志 tag 统一 `HG.Spider`，格式 `op=net host=… ms=…` / `cap=home ok` / `cap=home timeout 15000ms`。
- 不改 `AiiHttp` 的公开签名；`net` 直接调 `AiiHttp.getRaw(url, headers, 15)` 那族。
- 阶段 0 **不做**白名单的可配置化：`net` 先只允许 spider 自己声明的 `hosts`
  （从 `__spiderSite.hosts` 读，runtime 在注入后取一次并通过 bridge 校验）。

## 八、`web.spider`：配置怎么指向源码（2026-10-19 定型）

阶段 0 的源是硬编码读 assets 的。八家迁完之后，一份源配置怎么找到自己的 js，
这条约定换了两次，最终按 TVBox 的样子定下来。

### 现在的形状

```json
{
  "web": {
    "spider": "https://149.104.21.177.sslip.io/spiders/yhdm.js",
    "spiderArgs": ["api"]
  },
  "cover": { "mode": "plain", "allowedHosts": ["yhdm.one"] }
}
```

**`web.spider` 直接写源码地址。** 这是 TVBox 的模型：它的 `sites[]` 里每条配置
都带自己的 `spider` 字段指向源码，配置**自己声明**源码在哪。

### 为什么要改

第一版写的是纯 id（`"yhdm"`），装源时靠「配置和源码放同一个目录」去猜 `<id>.js`。

猜得到是运气，猜不到就是一句让人摸不着头脑的报错。而且一个配置想引用别处的源码
（比如官方维护的公共源）就没办法了 —— 这才是真正的限制。

### 两种写法都认

| 写法 | 行为 |
|---|---|
| `"https://…/yhdm.js"` | 取末段去 `.js` 当 id，源码从该地址下（推荐） |
| `"yhdm"` | 纯 id，回退到同目录 `<id>.js`（兼容已发布的配置） |

两种写法的解析规则必须**一字不差**地出现在两处：`app.js` 的 `spiderIdOf()`
和 `setup.js` 的 `addOneSource()`。写岔了的表现很难查 —— 装源时说装好了，
点进去报「找不到 spider: undefined」。

回归：`node scripts/spider-id-check.js`（直接从 `app.js` 抽函数跑，不抄一份）。

### 装源时到底发生什么

`setup.js` 的 `addOneSource(url)` 是唯一入口（设置页表单、源市场表单都走它）：

```
贴 .json  → 装配置 → 读 web.spider → 是地址就下那个 js / 是 id 就找同目录 → 装进 SpiderStore
贴 .js    → 只装源码，返回 needsConfig:true
```

**贴 js 不猜配置**，这是有意的：TVBox 模型里「源码」和「站配置」是两件事 ——
源码是可复用的解析器（苹果CMS 一个 js 覆盖几千个站），配置是某个具体站的参数
（接口地址、分类、封面域）。要求一个 `.js` 自带站点参数，等于要求它做它不该做的事。

### `spiderArgs`：源需要的配置项怎么传下去

spider 只拿到一个 `args`，拿不到配置。有的源需要自己的配置才知道往哪打
（苹果CMS 没有固定域名，接口地址只能由配置给）。

约定 `web.spiderArgs` 是一个键名数组，列出的键从合并后的 web 块抄进 args：

```json
{ "web": { "spider": "…/cms.js", "api": "https://…/api.php/provide/vod",
           "spiderArgs": ["api"] } }
```

为什么是「源声明要哪些」而不是把整个 web 块塞进去：web 块里有 `ui` / `categories` /
`fields`，动辄几十 KB，每次跨桥传一遍是白花的序列化成本；显式声明还是一份可读的
依赖清单。

**这个缺口是拆完适配器才暴露的**：`cms.js` 一直从 `args.api` 读接口地址，而
`spiderArgsFor` 从来没传过配置项 —— 于是「配置里写 `web.api`」是死的，源一直用
兜底域名跑，**表面完全看不出问题**。
