# 91porn：补上站点识别，修掉中文搜索

**日期**：2026-10-18
**站点**：`https://901.26702.app/`
**动的文件**：`Porn91Site.java`（补 probe / matchesUrl）、`Porn91Adapter.java`（percentDecode 改按 UTF-8 解）

---

## 一、原来缺的是「认站」

`Porn91Adapter` 835 行的解析一直都在，但 `Porn91Site` 只实现了 `/api/` 分流 —— **没有 probe**。
后果是用户把站点地址填进「设置源」根本加不进来：`load()` 会先 fetch 一次，拿到 42KB 的
HTML，然后报「返回的不是合法 JSON」。

补上之后：域名（901.26702.app / 91porn.com）+ 指纹（`/v.php` 里有 video-title 卡片、
至少 5 条 `view_video.php?viewkey=`）两道都能过。

配置里三样东西是现抓的，不能写死：

- **分类表**：站点导航栏里就十个 code（ori / hot / top / hd / rf / tf / long / longer / md / mf）。
  不认识的 code 站点回的是「全站最新」而不是 404 —— 所以只能写实测过的。
- **封面白名单**：封面在 CDN 上（实测 `1729130453.rsc.cdn77.org`），漏了就全是灰底。
  从首页 HTML 的 `src/poster/data-original` 里现抓，顺手把统计域名剔掉。
- **底部导航**：十个分类折成 5 + 更多。

## 二、中文搜索一直是 0 条

`percentDecode()` 老实现是逐字节 `(char) byte` 拼字符串：

```java
sb.append((char) ((hi << 4) | lo));   // 中文变成 Latin-1 乱码
```

对 ASCII 没问题，对中文就是把一个 UTF-8 字符的三个字节拆成三个字符（"自" → "è‡ª"）。
这个乱码串再被 `enc()` 编码回去，就是另一串字节，站点按那串搜 —— **0 条，且不报错**。

症状很有迷惑性：首页、详情、播放全正常，只有搜索永远空。因为只有搜索会把 URL 里的
中文参数解码一次再编码回去。

现在按字节收、按 UTF-8 解，往返用例 `编码解码往返` 钉住了。

## 四、播放那一段的坑

播放地址长这样：

```text
https://ccm.91p52.com/358999.mp4?st=<签名>&f=<token>
```

两个麻烦：

1. **证书链不完整。** `openssl s_client` 看得到 `* .91p52.com` 和 Let's Encrypt YE2，
   但 `Verify return code: 20 (unable to get local issuer certificate)` —— 服务器没发
   中间证书。浏览器能靠缓存/AIA 补，VLC 这类库不一定。表现是**加载圈一直转**，
   过一阵可能自己开始播。
2. **VLC 不走 App 的代理。** 页面本身是 `AiiHttp` 拉的（走代理），播放是 libVLC 自己
   建连接。规则一样：直连大概率被墙。

所以这个源「能不能播」取决于手机当下的网络能不能到 `ccm.91p52.com` —— 和页面能不能
打开是两件事。真机上实测能播，但首帧慢。

## 五、2026-10-18 晚：详情页每次换一部件（游客标记 `ga`）

用户报「点进去，片子跟标题封面对不上」。不是偶发，几乎每条都不对。

### 症状

同一个 `viewkey` 连请求五次，什么都不带：

```text
#1 mp4=855282   #2 mp4=878350   #3 mp4=864307   #4 mp4=874177   #5 mp4=876121
```

五次五个文件，标题十次都是同一个。把其中两张封面下下来看：一张金发白人在车里，
一张黑发在酒店 —— **不是同一部片**。

### 根因

站点把两件事拆开了：

- **标题**按 viewkey 取 → 永远对
- **媒体和封面**按会话取 → 没有会话标记时走「随便给一部」那条渲染路径

那个会话标记是一个叫 `ga` 的 cookie。站点在 `/`、`/index.php`、`/v.php?next=watch`、
甚至详情页自己都会下发（`Max-Age=100000000`，到 2029 年）。

带上它之后：

```text
Cookie: ga=1
1816005455 → 1252139   208573139 → 1252176
911802319  → 1252166   9e50cbb7… → 1252103
```

这四个数正好是首页那四张卡片的封面缩略图（`playvthumb_<id>`）。标题、封面、视频
终于是一条片了。

**列表页不受影响** —— 连拉两次，24 条的 thumb 和 viewkey 一个不差。所以症状只在
点进详情之后出现，看起来才像「列表是对的、详情串了」。

### 修法

`Porn91Adapter`：

```text
第一请求（不带 Cookie） → 从响应头 Set-Cookie 收 ga → 带着它**重取这一次**
之后所有请求都带 Cookie: ga=<值>        （进程内一次，之后零成本）
站点没下发时回退 ga=1                     （实测同样管用）
```

要点：

- **第一次请求的正文必须丢掉重取。** 那一份是随机片，拿它解析出来的标题封面全是错的。
  这一点比「有没有 cookie」更容易漏 —— 只加 Cookie 不重取，第一次还是会错。
- `AiiHttp` 加了一个重载：`getRaw(url, headers, timeout, cookieOut)`。`Set-Cookie`
  只在响应头里，body 一个字节都没有 —— 之前 AiiHttp 只回 `byte[]`，拿不到。
- `ga` 的值不校验内容，`1` / `abc` / 真值都试过，同一批 viewkey 出来的都是同一部片。
  所以兜底值能兜住「哪天 Set-Cookie 被中间设备剥掉」。
- `forgetGuest()` 会把**游客标记和 META_CACHE 一起清**。标记错着的时候缓存里那份
  详情也是错的，只清标记会让缓存把错的那份吐回来。

### 一个没成立的判据

一开始想断言「卡片封面 == 详情封面」，跑 live 测试发现站点上不成立：同一个封面会被
两条不同的 viewkey 共用（同一段片子被不同人重复投稿），实测 8 条里 2 条对不上，
而同一条连取又是稳定的。所以那条判据会把站点的去重行为误判成 bug，删掉了。

现在钉的是两条：

| 用例 | 钉什么 |
|---|---|
| `同一条连取三次封面不变` | 随机渲染没了（改之前三次三个值） |
| `封面和播放直链指向同一部` | 同一次渲染内部自洽：`thumb/1252139.jpg` ↔ `mp43/1252139.mp4` |

离线那三条钉 `requestHeaders` 带不带 `Cookie`、`pickGuest` 只认 `ga`、
`chooseGuest` 拣不到时回退。

## 六、列表页在乱写：拿详情页把卡片盖一遍（1.0.28）

上一节修完了「详情页随机」，但还是有人报「点缩略图是一个，点进去封面换了一个」。

### 这次是列表页的问题

真机 + 浏览器两边对过，91porn 的网格页（`/v.php`、分类页）**每张卡上有三个 id**：

```text
href      view_video.php?viewkey=37c6a937d320a73de273
容器 id   <div class="thumb-overlay" id="playvthumb_1252669">
封面      <img src="…/thumb/1252644.jpg">
```

三个一致时点进去对得上；不一致的就是「换封面」的那些。实测一页 40 张卡里
**12 个 viewkey 重复出现**，`37c6a937…` 一张页里出现 4 次，配 4 个不同封面。
`/v.php` 两次渲染，24 条里 10 条封面会变；分类页 12 条。

**用 Chrome 直接开站，现象一样** —— 不是我们解析错，是站点给爬虫的迷魂阵。
反证：**搜索页是干净的**（两次渲染 0 变化、3/3 与详情一致）。站点做得到，
就是首页不给。

### 修法：先出图，再逐条校正

不指望网格页了。列表照旧返回（快），前端拿到之后调一个新接口
`/api/reconcile?ids=a,b,c`，Java 用 4 个线程并发拉这些 id 的详情（命中
`META_CACHE` 就不发请求），回一份 `{id,title,cover,badge}`，前端把卡片和
`state` 里的对象一起改掉，再重画一次。

```text
首页     3.7s 出列表（12 条 + 精选 8 条）
        ↓ 同时 24 个详情请求，4 线程
        ~2s 后封面/标题自己改正，用户看着卡片一张张换对
二次进入  详情全在 META_CACHE 里，零请求
```

几个必须记住的点：

- **`CACHE_LIMIT` 从 16 提到 64。** 一页 24 条，缓存比一页小等于每次进首页都全量重拉。
- **并发压到 4。** 这个站对非浏览器流量有静默处理（UA 不对回 200 + 0 字节），
  24 个并发有被限流的风险。整轮预算 12s，超时的条目保留原值。
- **校正失败不影响渲染。** 单条失败就用站点原样，一张坏卡不能拖住整页。
- 已校正的 id 记在 `reconciledIds` 里，同一次会话不重复请求；整批失败会把 id
  吐回去，下次还能重试。

### 测试

| 用例 | 钉什么 |
|---|---|
| `校正接口能给出详情真值`（live） | 接口回来的标题/封面必须和各自详情页逐字段一致 |
| `reconcileRejectsEmptyIds`（离线） | 没给 id 直接报错，不发请求 |

前端那一层没法在 JVM 里测，靠真机验：装 1.0.28 之后抓 5 张卡，封面 5/5 与详情一致
（改之前同一批是 2/5），logcat 里能看到 24 条 `GET …/view_video.php`。

## 七、高清分类 0 部作品（1.0.29）

真机点底部「高清」tab，页面空着，右上角「已显示 0 部作品」。

原因很简单：**那个分类整页的卡片都走 `view_video_hd.php`**，不是 `view_video.php`。

```html
<a href="https://901.26702.app/view_video_hd.php?viewkey=518377ab…&category=top">
```

`CARD_RE` 只认 `view_video\.php`，于是一条都匹配不上。整站扫了一遍，链接形态就两种：

```text
view_video.php      387 条   （首页、热门、原创、本周榜、精选…）
view_video_hd.php    45 条   （category=hd 整页）
```

改法：正则放宽成 `view_video(?:_hd)?\.php`。**详情和播放仍然用 `view_video.php`** ——
实测同一个 id 走 `view_video.php` 拿得到标题、poster 和直链（`1248420.mp4`，与
poster 同号），而 `view_video_hd.php` 那页只有标题，没有 poster 也没有 source。

## 八、校正只补了首页，分类页还是旧封面

第一版 `reconcileCards` 用 `Set` 记「这个 id 请求过」，首页补好之后切到高清 tab，
同一批 id 又变回网格页的假封面 —— 因为它们是**两个不同的对象**（首页数组一份、
分类页数组一份），Set 里记着 id 就不去补第二份了。

改成 `Map<id, 真值>`：进来先用已有的真值套一遍（零请求），缺的 id 才发请求。
顺带补上分类页的钩子 —— 之前只挂了首页、`更多`、标签列表、搜索，`goCategory`
这条路漏了。

## 九、「全部类型」页 0 个标签（1.0.30）

真机点「全部类型 → 全部类型」，标题写着「0 个标签」，整页空。

这个站确实没有话题标签，但它**顶部那排分类链接就是它的标签栏**：

```text
91原创 / 当前最热 / 本月最热 / 10分钟以上 / 20分钟以上
本月收藏 / 最近加精 / 高清 / 本月讨论 / 收藏最多
```

以前 `tags()` 直接返回空数组，理由是「没有标签体系」。四处一起断：

| 位置 | 原来 | 现在 |
|---|---|---|
| `Porn91Adapter.tags()` | 返回空数组 | 从站点导航里抠 `v.php?category=xx` + 链接文字 |
| `Porn91Site` paths | 没有 `tag-list` | `/api/videos?cate_id={slug}&page={page}`（标签就是分类） |
| `Porn91Site` ui | 没有 `tagGroups` | `[["category","分类"]]` |
| 前端 `goTag` | 一律加「短剧·」前缀 | 只有源真的按短剧/漫剧分标签时才加 |

**标签名和分类码都取站点自己的**，不写死一份表 —— 多一个少一个分类不用改代码；
导航抓不到才退回 `CATEGORIES` 那十个。

顺带修了 `renderTags` 的一个老毛病：它只渲染 `ui.tagGroups` 里声明过的组，
**配置没声明的组一个都不显示**。91porn 那份 `user-source.json` 是早前版本生成的，
里面没有 `tagGroups`，于是「10 个标签」写在标题上、页面却空 —— 数字对、内容没有。
现在配置里没声明的组按数据补上，标题用 `GROUP_TITLE` 兜底。

### 一个容易踩的坑：旧配置不会自动更新

`use()` 切换源时会**优先用本地缓存那份配置**（并在后台刷新）。所以给 `probe()`
加了新路径之后，已经加过这个源的用户不会立刻用上 —— 缓存里还是旧结构。
真机上就是：重新 `__source:set` 也没用，得先 `__source:refresh?url=…` 把缓存刷了，
再切一次，然后**冷启动**（`restart` 那次 recreate 有时不生效，profile 还是旧的）。

这也是「全部类型 0 个标签」在 1.0.30 装完还复现了一次的原因，记在这儿。
