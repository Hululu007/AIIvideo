# 51吃瓜 适配（2026-10-19）

`https://51cg1.com/` 逆向 + spider 接入。形态上跟 pornhub 是一类：服务端渲染、
没有盾、没有 JSON 接口。麻烦的地方在别处——封面藏在 `<script>` 参数里，播放是
带 AES-128 的 HLS 且分片和 master 不同域。

## 一、形态

裸 curl 带安卓 Chrome UA：`https://51cg1.com/` → 200、260-270KB、1.8 秒。
`<!-- time (2026-10-19 22:49:40) -->` 是它自己的构建戳。

试过 WordPress 那套（`/wp-json/`、`/wp-admin/admin-ajax.php`）：一个都没有。
它是自研的 Typecho 系主题：

- 文章：`/archives/<数字id>/`
- 分类：`/category/<短名>/`
- 搜索：`/search/<关键词>/`
- 主题目录：`/usr/themes/Mirages/`
- 播放器：`/usr/plugins/DPlayer/`

顺手也确认了 RSS 存在（`/feed/`，10 条），但条目不够翻页用，最后没走它。

## 二、卡片：封面写在 `<script>` 里

```html
<div class="post-card" id="post-card-279391">
  <script>
    loadBannerDirect('https://pic.gyezbp.cn/upload_01/xiao/20261019/….jpeg', '',
      document.querySelector('#post-card-279391'), '-1', …);
  </script>
  <h2 class="post-card-title" itemprop="headline">
    51吃瓜2026/10/18瓜友求瓜合集 …
    <div class="wrap"><span class="wraps">热搜 HOT</span></div>
  </h2>
  <div class="post-card-info">
    <span itemprop="datePublished" content="2026-10-19T10:51:00+00:00">…</span>
  </div>
</div>
```

两个坑：

**封面不在 `<img src>` 里。** 站点用背景图 + JS 懒加载，DOM 里没有可直接取的
`src`。唯一稳的来源是 `loadBannerDirect('…')` 这个脚本的第一个参数。所以正则是抓
脚本参数，不是抓属性。

**标题里嵌着角标。** 那个 `<div class="wrap"><span class="wraps">热搜 HOT</span></div>`
在 `<h2>` 内部，直接 `stripTags` 会把「热搜 HOT」粘到标题尾巴上，卡片看起来像
标题被截断。所以先整块删掉 `wrap` 再剥标签。

## 三、分页：三种页型三套 URL

| 页型 | 第 1 页 | 第 N 页 |
|---|---|---|
| 首页 | `/` | `/page/N/` |
| 分类 | `/category/<slug>/` | `/category/<slug>/N/` |
| 搜索 | `/search/<关键词>/` | `/search/<关键词>/N/` |

**别拿 `/page/N/` 去翻分类页。** 实测 `/category/whhl/page/2/` 回 **403**（2,501 字节
的 WAF 拦截页），而 `/category/whhl/2/` 正常 200。同理搜索页 `/search/x/page/2/`
回 **410 Gone**，`/search/x/2/` 才 200。这两个错误页都长得像正常页面，只有状态码
不一样。

三种页都有 `<link rel="next">`，所以 `hasMore` 统一按它判。越界页
（`/page/50000/`、`/category/whhl/5000/`）回 **404 且 0 张卡**，而 `net` 对非 2xx
直接抛错——判错一次用户看到的就是错误块，不是「到底了」。

## 四、播放：DPlayer 的 data-config

详情页里播放器容器带一个 `data-config='{…JSON…}'`，是**合法 JSON**（实测 8 条全过）：

```json
{
  "video":      {"url": "https://hls.weagdnz.cn/videos5/<md5>/<md5>.m3u8?auth_key=…", "type": "hls"},
  "video_h265": {"url": "https://hls.weagdnz.cn/m3m/<长hex>.m3u8?auth_key=…", "type": "hls"},
  …
}
```

H.265 那条不是每条都有（8 条里 6 条有）。所以 `alts` 是 1~2 条。

拿到的 m3u8 **不是 master**，是媒体列表，而且加密：

```
#EXTM3U
#EXT-X-VERSION:3
#EXT-X-KEY:METHOD=AES-128,URI="https://tx.doudou520.online/…/crypt.key?auth_key=…",IV=0x419f49bb…
#EXTINF:5.000,
https://tx.doudou520.online/videos5/<md5>/<md5>0.ts?auth_key=…
```

关键点：**分片主机和 master 不是同一个域**。master 在 `hls.weagdnz.cn`，
分片/key 在 `tx.doudou520.online` / `mts.hhjd.mobi` / `ts.zhixunkeji.xyz` 之间轮换
（抽样 8 条：tx 出现 4 次、mts 2 次、ts 2 次）。

播放层那边 `VlcRelay.rewriteM3u8` **只改写非 `#` 开头的行**，所以：

- 分片（ts 行）会被包进 `http://127.0.0.1:PORT/s?u=…` → 走中继 → 受 `http.hosts` 管；
- `#EXT-X-KEY` 那行的 URI 不改写 → **VLC 自己去取 crypt.key**，不经中继。

两条路都不经过站点本身，所以这个源在播放阶段不再打 51cg1.com。副作用是
`crypt.key` 那一跳不受白名单约束——如果哪天网络环境需要代理才能取到它，症状会是
「播放器一直转圈、日志里分片都在 200」。

## 五、图文帖要降级，不能报错

这个站很大一部分是纯图文爆料（`/archives/279391/` 就没有播放器）。没有
`data-config` 或没有 `video.url` 时，`play` 返回 `reason: 'no-source'`，
不塞坏地址——按契约 §5.3 那是**正确的降级**，界面显示正常内容加一句说明。
硬塞空地址会落到 `state: 'empty'`，文案变成「这个源没有给出这一集的播放地址」,
用户会以为是解析坏了。

## 六、搜索

`/search/<关键词>/`，关键词必须 `encodeURIComponent`。中文裸传会路由不到
（回首页模板）。`?s=` 那条是老 WP 习惯，这里 301 到 `/`，别用。

## 七、验证

离线回归 `node scripts/spider-check.js …/51cg.js`：**23 条断言全绿**。

```
✓ home 7 条   ✓ category 3 条   ✓ search 3 条   ✓ detail 6 条   ✓ play 4 条
```

夹具裁法同 pornhub：留前 60KB（`<link rel="next">` 在这儿）+ 头 12 张卡的原始标记，
卡片标记一字节没改。另外**两类详情页各留一份**——视频帖（带 `data-config`）和
图文帖（没有）——因为「图文帖降级成 reason」是这个站独有的分支。

断言盯的点：

- 首条 id `279044` / `279407` / `279423`（三个页型各一条，防止路由串了）；
- 封面全部来自 `pic.gyezbp.cn`（证明抓的是脚本参数）；
- 标题里没有残留的「热搜 HOT」；
- 详情标签从「关键词：#…#…」拆出 > 3 个；
- 播放两条线路、默认 h264、给的是 `hls.weagdnz.cn` 上带 `auth_key` 的 m3u8。

全量 `node scripts/spider-all-check.js`：**12 个源，12 个配了回归，12 个全过**。

## 九、还没验的

真机没跑（设备锁屏）。离线证明的是解析，没证明的：

1. AES-128 的 key 那一跳能不能通。这是这个源最不确定的地方——`#EXT-X-KEY` 不被
   `rewriteM3u8` 改写，VLC 直连 `tx.doudou520.online`。如果设备网络到那个域不通，
   表现是「m3u8 拿到了、分片也 200、但画面黑」；
2. 分片主机轮换到池外的新域 —— `http.hosts` 是按抽样列的四个。但注意这张表
   目前**不生效**：只有 `hxm/http.js` 那条 JS 播放器路径会走 `PlaybackHttpBridge`，
   VLC 走的 `VlcRelay` 不读它（引用数 0）。所以轮换成新域不会报白名单，只会在
   relay 日志里体现成连接失败；
3. 首页 25 张卡的封面有没有因为 `pic.gyezbp.cn` 之外的新图床而灰块。

真机日志：

```bash
adb logcat -s HG.Spider
# cap=__meta ok … caps=["home","category","search","detail","play"]
# cap=home ok ms=…
# [relay] 播放列表改写 N 条 @…
```

黑屏但分片 200 → 看 key 那一跳（`crypt.key` 是 VLC 直取的，不经中继）；
分片 403/超时 → 那是 CDN 域的问题，跟 `http.hosts` 无关；灰块 → 补 `cover.allowedHosts`。
