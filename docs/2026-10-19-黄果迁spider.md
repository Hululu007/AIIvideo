# 黄果短剧：从内置源迁成 spider 源（2026-10-19 晚）

## 一、先认一个错

上一轮我把黄果源从壳里删掉，理由是「它没有接口可迁移」——依据是 `site-default.json`
里 `origin` 是空串、`web` 下没有 `paths`。

那个判断错在两处：没翻 git 历史，也没探站点。

- 路径一直在 git 里。`a601dc5`「删掉默认接口路径」之前那版有完整的一份：
  `/api/home`、`/api/videos/{id}`、`/api/videos/{id}/play?ep=`、`/api/tags` …
- 站点一直活着。`https://huangguoai.com/api/home` 现在还是 200 / 20085 字节。

缺的只有 `origin`。填回去，它就是一个普通的、可迁移的源。

## 二、接口（2026-10-19 实测，全部 200）

```
GET /api/home                               banners / featured / latest / cate_rec / topic_rec
GET /api/videos?cate_id=24&page=1&size=20   {items, pagination{page,pages,size,total}}
GET /api/search?q=都市&page=1                {items, pagination}
GET /api/videos/7628                         详情 + episodes[{duration,ep_num,status,title}]
GET /api/videos/7628/play?ep=1               video_url（m3u8 + auth_key 签名）
GET /api/tags                                categories[10].tags[156]
```

`status:1` 表示成功，`msg` 空。返回体统一是 `{data, status, msg, req_time}`。

## 三、spider 怎么写

七个能力，全部走 JSON，没有 HTML 解析：

| cap | 接口 | 说明 |
|---|---|---|
| home | /api/home | 五块摊平成 items（featured → latest → cate_rec），跨段去重 |
| category | /api/videos?cate_id= | slug 是数字 cate_id |
| search | /api/search?q= | 空词不发请求 |
| detail | /api/videos/{id} | episodes 映射成前端要的 `{no,title,ref,episodeNumber,duration}` |
| play | /api/videos/{id}/play?ep= | 每次实时取，**零缓存**（auth_key 有有效期） |
| tags | /api/tags | 10 个分区 156 个标签，分区 code 直接当 group |
| tagList | /api/search?q=<标签名> | 接口没有「按标签 id 列表」，沿用旧配置的搜索法 |

三个和别家不一样的地方，都写进注释了：

1. **分类 id 是数字**（24 成人短剧 / 25 成人漫剧 / 26 AI换脸 / 27 AI魔改），不是 slug。
2. **列表项自带 `episode_count`**，卡片角标用「N集」比时长有信息量。
3. **封面和播放地址都带 `auth_key`**（`?auth_key=1792412972-0-0-…`），是签名不是 cookie。

## 四、两个坑（都是实测撞出来的）

**首页封面是相对路径。** `/api/home` 给的是 `/upload_01/upload/…`，而列表接口给的是
完整地址 `https://pic.drleao.cn/upload_01/…?auth_key=…`。同一个站点两套写法，不补
`PIC + path` 这一层，首页就是一片灰底——封面请求 404，而报错在渲染层根本看不到。

**tags 配置声明 10 个分区，实际只有 9 个有标签。** 「吃瓜黑料」那组现在是空的。
空组不渲染，所以离线断言写 9 而不是 10（写 10 会逼着去伪造一组空标签）。

## 六、真机上没跑通：是网络，不是代码

在手机上（23113RKC6C）装完、切过去，首页报：

```
net huangguoai.com → 代理 profile=有 mode=builtin proxy=有
cap=home fail: 黄果接口请求失败 /api/home：net 失败：Read timed out
```

- 代理节点（罗马尼亚 · 布加勒斯特 2）访问 huangguoai.com：**30 秒读超时**
- 切成直连（`mode=direct`）再试：**Connection reset**（`huangguoai.com` 在
  `DirectHosts` 里，直连会走 DoH 解析，而阿里/腾讯对它有污染答案）

同一个 URL 从本机（走本地代理）和香港 relay（直连）都是 200 —— 所以接口、代码、
配置都没问题，是**这台手机当前用的节点到不了那个站**。

要用这个源，需要换一个能访问 `huangguoai.com` 的节点。源本身已经装好了，换完节点
直接能用。

## 六点五、钉 IP 与封面解密：旧配置里那两条必须抄过来

你贴的那份旧 REST 配置里有两样东西，我的第一版漏了，直接导致真机表现不一样：

**① `hosts` 钉 IP。** 旧配置写着：

```json
"hosts": {
  "huangguoai.com": ["103.41.125.230", "43.229.39.228"]
}
```

`_why` 里说得很清楚：运营商 DNS 回证书过期的 IP、阿里 DoH 回 0.0.0.0、腾讯 DoH 五个
地址里只有一两个能用。不钉 IP 就只能听 DNS 的，而 DNS 给的是废答案。

spider 的 `net` 走的是 `AiiHttp`，读的正是顶层 `hosts` 这张表 —— 所以这条对 spider 源
同样有效。补上之后日志里出现：

```
[http] 按配置钉死 huangguoai.com → 2 个地址
```

**② `cover` 是 AES-CBC 加密图。** 旧配置的 `mode: aes-cbc` + `key` / `iv` /
`allowedHosts` 四个 pic 域，第一版我写成了 `mode: plain` —— 封面会全是裂图。

现在这份 `huangguo.json` 就是把旧配置里「网络怎么走」和「封面怎么解」原样搬过来，
只把 `paths` 去掉（内容走 spider，不走 `/api` 路径模板）。

## 七、顺带记一个缺口

这次本想用「源声明直连」绕开节点问题（在 `__spiderSite` 里写 `direct: [...]`），
但发现两件事：

1. 这个机制**没实现**（文档「四点五」里讨论过三种出路，最后一条都没落地）。
2. 就算实现了，这次也救不了 —— 直连是 `Connection reset`，不是解析慢。

所以缺口照记：`DirectHosts` 仍只能靠改 Java 代码加域名，源无法自己声明。
哪天遇到「必须直连、且直连能通」的站，这个口子要开。
