2026-10-16 拆。**现在整条链都通了**，且在真机上跑通了端到端播放。

```text
age_ 密文  →  真 m3u8
```

## 链路

```text
①  agedm 详情  video.playlists = { "xigua": [["第01集", "age_…"], …], … }
       给的是**密文**，不是地址。player_vip（哪些线路能直连）在**响应顶层**，不在 video 里。

②  GET  https://jx.wuzhoupai.com:8443/vip/?url=<token>
       token 原样拼进地址 —— 它自带 %2F，再 encodeURIComponent 一次会变成 %252F，
       对面解析不出来，只丢一个 32 位的占位 Vurl 回来（然后整条链就废了）。★踩过

   响应 HTML 里嵌着这一轮的会话参数：
       var Vurl = "<96 位 hex，随线路不同长度是 32 的整数倍>"
       var Time = "<秒级时间戳>"
       var Version = "V3.2"
       <meta ... id="<10 位数字>">            ← 两个 meta 的 id
       <meta name="viewport" ... id="viewport<…>">

③  url 字段 = Vurl **原样**（页面里 url === window.Vurl，别再加密一次）★踩过
    Params = hxm_encrypt(JSON{"url","wap","ios","host","referer","time"})
    sign   = hxm_encrypt("<host> | <UUID> | <time> | <Version> | <完整 Params>")

    POST https://jx.wuzhoupai.com:8443/vip/Api.php
      Content-Type: application/x-www-form-urlencoded; charset=UTF-8
      X-Requested-With: XMLHttpRequest          ← 少了它拿 Code=1
      Video-Parse-Sign / -Time / -Uuid / -Version: V3.2
      body: Params=<hex 大写>

④  → {"Status":1,"Appkey":"<32 位 hex>","Version":"V3.2","Code":10,"Data":"<hex>"}
    Code=10 才是成功。Code=1 是「没读懂请求」（换个形状的信号）。

⑤  密钥 = md5( Code + id1 + id2去掉"viewport" + Appkey + Version )   ← 十六进制小写
      key = 前 16 个**字符**（当 ASCII 字节用，AES-128）
      iv  = 后 16 个字符
    AES-128-CBC / PKCS7 解 Data  →  {"url":"<hex>","code":200,"msg":"数据正常"}

⑥  m3u8 = decodeURIComponent( hxm_decrypt(json.url) )
```

## `hxm_encrypt` / `hxm_decrypt`

整个签名体系就这两个函数，**不是 JS**，是一个 **307063 字节的 TinyGo wasm**（基于 Go 1.16）：

```text
导出：main.AesEncryptCBC  main.AesDecryptCBC  main.Encrypt  main.Decrypt  main.pkcs
二进制里还留着 C:\Users\Admin\AppData\Local\tinygo\goroot-go1.16-…\src\…
sha256  c2388422ee32151b5293bad33073134cffa6f60329b07e613c3da70aabb147f7
```

import 的是 `wasi_snapshot_preview1.fd_write` + `env.syscall/js.*`（**TinyGo 的 ABI，不是标准 Go 的**）。
粘合代码被内联在 `global.min.js` 里（注释写着 `go_js_wasm_exec Library v1.0.0`）。

跑起来需要：一个最小浏览器环境（`harness/shim.cjs`）+ **在 `go.run()` 之前**设好
`window.Domain = "jx.wuzhoupai.com"` —— 它初始化时读一次，**必须是精确这个值**：

```text
"jx.wuzhoupai.com"   → enc('test') = fbe2789fdb0178f0c0b3358145a2ea62   ✓ 与浏览器一致
"JX.WUZHOUPAI.COM"   → enc('test') = 45ef284faae67043bcdb8b6d70b2aa89
"jx.wuzhoupai.co"    → 同上
"aaaaaaaaaaaaaaaa"   → 同上
```

反汇编 `main.main` 看得到它在**逐字节比较**这个字符串（`runtime.memequal`），然后按表选密钥。

### 密钥没抠出来

坦白讲：**放弃抠密钥，改用对面自己的 wasm 当黑盒。**

试过的路子（都没成）：

| 试法 | 结果 |
|---|---|
| 全内存扫描，每字节偏移 × 16/24/32 字节都当 AES 密钥 | 零命中（判据：从 `enc('')` 反推 IV，再用 `enc('test')` 验证第二块 —— 单块是自洽的没有区分力） |
| 域名派生的各种编码（md5/sha/base64/utf16le/大小写/反转） | 零命中 |
| 二进制里靠近域名常量的字符串（含作者留的嘲讽 `ni po jie ni`）的全子串 | 零命中 |
| ECB / CBC / CFB / OFB / CTR | 零命中 |
| 按 Go 字符串字面量的 (指针,长度) 关系找 | 那条只用于 `Get("window")`，长度 6 |

作者是刻意防着的：域名硬编码 + 密钥查表 + jsjiami 混淆藏入口。

### 两个绕不开的坎

**CORS**：浏览器直连 `Api.php` 不行 —— 预检响应里只有 `access-control-allow-origin`，
**没有 `access-control-allow-headers`**，`Video-Parse-*` 那几个自定义头过不去。

**CSP**：页面是 `connect-src 'none'`（刻意收紧的），网络一律走 Java。所以网络走
`UserSource` 的 `__http:` 出口（只放行 https + 主机白名单）。

结果就是 `HG_HTTP` —— JS 编排、Java 发请求。签名要跑 wasm，所以**两边都得用上**。

### CSP 只动了一个关键字

`script-src` 加了 `'wasm-unsafe-eval'`（没这个 Chrome 拒绝 `WebAssembly.instantiate`）。
`connect-src` **保持 `'none'` 不动** —— wasm 走 `<script>` 内联进来，不需要网络。

## 踩过的坑（都验证过）

| 现象 | 原因 |
|---|---|
| `Code=1`，Data 只有 192 位 | 几个头没带全（主要 `X-Requested-With`）；或者 Vurl 是 32 位占位符 |
| Vurl 只有 32 位 | token 被二次编码（`%2F` → `%252F`） |
| `Code=4` | sign 里的 Params 被截断了，要用**完整**的 |
| 解出来是乱码 | Data 不是 `hxm_decrypt` 解的，要先 `AES-128-CBC(md5 拆两半)` 解出 JSON，再解 JSON 里的 `url` |
| 「缺少参数 url」 | url 字段做成了 `enc(Vurl)`，应该是 `Vurl` 原样 |
| `Expected URL scheme 'http'…` | 配置里没有 `origin` 又没 `adapter`，`/api/…` 落到普通路径上 |
| 播放地址为空 | `adaptEpisode` 的 `pick(raw,'source')` 走配置别名表，适配器按原名返回时取不到 |
