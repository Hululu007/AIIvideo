# 2026-10-18：代理分流、播放返回栈、VLC 黑屏三连修

这一轮三个问题全是真机上撞出来的，彼此独立但同一天修完。按发现顺序记。

---

## 一、代理全局拖垮直连源 —— DirectHosts 分流

### 现象

看 AGE动漫 报 `解析失败：HTTP 失败：SSLHandshakeException connection closed`；首页有时报 `unexpected end of stream on https://api.agedm.io/...`。

### 实测数据（真机，内置核心开着，节点荷兰 84.17.47.125:9002）

| 目标 | 走代理 | 直连 |
|---|---|---|
| `api.agedm.io/v2/home-list` | 200，2.49s | 200，1.36s |
| `jx.wuzhoupai.com:8443`（播放解析） | **000，4.6s，SSL 断** | **200，0.17s** |
| `jx.wuzhoupai.com:443` | 000 | 000（自签证书，2019 年签，`O=Default Company Ltd`）|

### 根因

代理三档开关（直连/内置核心/外部地址）是**全局**的。为了 91porn / ASMR 开了内置核心，AGEdm 和黄果这些直连本来就通的源也全被拖着走那条节点。节点一抖，传输层断 —— 两个域名、两种报错，同一时刻出现。

`:443` 自签是顺带查清的，不是主因；`:8443` 直连可用。

### 三个出口（这是关键认知）

代理流量从三个地方出去，一张表要同时管住：

1. **`AiiHttp`** —— 接口/解析/`__http` 桥，OkHttp `route.proxy`。覆盖外部代理模式（流量不经过 Xray）。
2. **`VlcRelay.wrap` → `MediaProxy.relayClient`** —— VLC 的 `:socks=`/`:http-proxy=` 选项在这套构建上全部无效（实测 SOCKS 端口零连接），所以视频流走「换地址」：VLC 播 `http://127.0.0.1:<port>/s?u=<原始地址>`，背后 OkHttp 拉 CDN，`relayClient` 跟随 `effectiveProxy()`。
3. **`XrayConfig`** —— 内置核心模式下从本地 SOCKS 进来的流量。

### 改法（A 骨架 + B 首发表）

新类 `DirectHosts`：显式域名表（没有 geoip/geosite，只能写显式域名），子域后缀匹配。当前七条：`agedm.io`、`jx.wuzhoupai.com`、`xcdn.khfed.com`、`bfzyapi.com`、`149.104.21.177.sslip.io`、`cab3f.nt17g20k.cc`、`huangguoai.com`。

- `AiiHttp` 三个接代理的点（`rawWith`、`getOnce`、`getWith`）命中表就现拼一个不带代理的 client（缓存的 client 按代理串判等，不能改，只能 new —— 接口级请求量小，开销可忽略）。
- `VlcRelay.wrap` 命中表直接 `return null`，VLC 拉原始地址直连，连本地中继一跳都省了。`MediaProxy.relayClient` 不用改：能到它手里的 URL 已全被 `wrap` 筛过。
- `XrayConfig.routing()` 把表生成一条 `domain: [...] → direct` 规则（Xray 的 `domain:` 自带子域语义）。

**以后新接直连可用的源，往 `DirectHosts.HOSTS` 加一行，三个出口自动生效。**

### 为什么以前没暴露

以前 AGE动漫 直连、91porn 单独折腾，没同时开代理。这次为 91porn 开了内置核心，全局生效，AGEdm 跟着遭殃。

## 二、播放返回栈死循环 + 「返回设置」落首页 —— `hgBack` 漏分支

两个前端路由 bug，都在 `app.js` 的 `window.hgBack` / `hgResume` 附近。

### 2a. 视频 → 选集 → 返回来回循环

链路：选集点集数 → `feed-player.openAt()` 把 `state.route` 改成 `'feed'`（不走 `setRoute`），退出原生播放器 → `hgResume` 的 `route === 'feed'` 分支调 `goDetail(back)`。`goDetail` 看到 route 不是 `'detail'` 走全量路径，`rememberScreen()` 把**当前屏幕——「正在打开播放器…」的 boot 残页**抓下来当 `state.previous`，把真正的返回目标覆盖了。之后：选集按返回 → `returnFromDetail()` 还原出残页；再按返回 → route 是 `'feed'` → `feedClose()` 拨回 `'detail'` 渲染选集 —— 无限循环。

**修法**：`hgResume` 里先把 `feedPlayer.cleanup()`、`state.route = 'detail'` 归位，再进 `goDetail`，boot 残页不再污染 `state.previous`。

### 2b. 「返回设置」返回了首页

`hgBack()` 里源设置、代理设置、播放器设置、市场四个子页没有分支，全掉进最后的 `goHome()` 兜底。这四个页面各有自己的返回快照（`sourceReturn` / `proxyReturn` / `playerReturn` / `marketReturn`），补四个分支即可，和账号管理页同一条路。**老坑，一直没暴露是因为平时都从设置页进去按返回。**

## 三、VLC 播放器两处显示 bug

### 3a. 第 N 集进来有声无画

现象：选第 1 集有画面，直接选第 N 集只有声音。

真机日志实锤（`adb logcat -s VLC:*`）：

```text
libvlc window: request 1 not implemented
libvlc video output: video output creation failed
libvlc decoder: failed to create video output
libvlc decoder: Opaque Vout request failed
[h264 @ ...] get_buffer() failed / no frame!
```

解码器拿不到 vout，帧全丢 —— 音频流照常走。

**根因**：feed 模式是竖向 RecyclerView + PagerSnapHelper 当翻页器，`buildUi()` 建好后**从来没有滚到 payload 指定的集数**。初始布局永远落在第 0 页，从第 3 集进来 `curPos=2`，`activate(2)` 解析好地址调 `playPage → attachVout`，但 `pageAt(2)` 是 null，vout 静默跳过，之后没人补。第 1 集正常纯属巧合（`index=0` 恰好是初始页）。

**修法**：`setAdapter` 后 `pager.post(() → pager.scrollToPosition(curPos))`，必须 post 一拍等布局完成。

### 3b. 播放器上下两道常驻暗带

`buildUi()` 加了两条渐变 scrim（顶 85% 黑/130dp、底/170dp）给控件垫底，但 `setControlsVisible` 收控件时只动 topBar/bottomBar，scrim 从不参与 —— 控件收了渐变还在，上下永远压着两道死黑带。

**修法**：`setControlsVisible` 里 scrim 的 alpha 跟着控件一起 180ms 淡入淡出。

## 四、详情页「永远加载中」与返回失灵（16:35 追补）

现象：详情页停在「正在获取内容… / 正在加载… / 正在获取选集…」，按返回没反应。

实测结论（逐条排除后）：

- **缓存是命中的**（`cache detail:<id> hit=true`）。慢只在冷缓存时：CMS 源的
  `/api/videos/{id}` 实测 0.3–6.5 秒波动（同一台机、同一条网络），当天两次
  卸载重装清空了 localStorage，所以「有缓存」这个前提不成立。
- **返回在各条路径上实测都能回首页**（列表→详情、首页卡片→详情、播放器退出→详情）。
  但排查过程中挖出两个会让它「看起来失灵」的隐患，都修了。

三处改动：

1. **桥调用加 30 秒超时**（`bridgeCall`）。原来 JS 侧等 Java 回调，没有任何超时：
   Java 那侧一旦因为 Activity 重建、线程池卡住、请求丢失而不回调，这个 Promise
   永远不 settle —— 页面永远 loading，连错误页都进不去。这是「永远加载中」唯一
   能解释通的机制。Java 读超时 15 秒，30 秒给 CMS 偶尔要连两个接口留余量。
2. **`hgResume` 里 `feedPlayer.resume()` 包 try/catch**。它一抛异常，整个
   `hgResume` 中断，`state.route` 就永久停在 `'feed'`；之后每次按返回都被
   `feedClose()` 拨回详情页 —— 用户看到的就是「返回没反应/又回到选集」。
3. **`goDetail` 不把 boot 占位页当返回目标**。从播放器回来时 content 里还留着
   「正在打开播放器…」的 `.feed-boot`，原先会被 `rememberScreen()` 抓成
   `state.previous`，返回时还原出那一屏残页。现在检测到占位页先清掉再记。

## 验证记录

- 代理分流：单测全绿（`testDebugUnitTest`），装机后 AGE动漫 走直连正常播放。
- 播放返回栈：选集 → 播放 → 返回 → 返回，不再出残页死循环；四个设置子页「返回设置」都落回设置页。
- VLC 黑屏：修前点第 3 集 logcat 刷 `video output creation failed`；修后同路径 vout 创建成功、decoder 输出 1088x608，零 vout 错误。scrim 收控件后干净消失。

## 排查手段备忘

- 播放器 vout 类问题：`adb logcat -s VLC:*`，认准 `video output creation failed` / `Opaque Vout request failed` / `get_buffer() failed` 三连 —— 这是有声无画的标准签名。
- 前端路由问题：`app.js` 里 `hgBack` 的分支顺序是契约，新子页加进来必须同步加分支，否则掉进 `goHome()` 兜底。
- 代理类问题：先分清流量走哪个出口（AiiHttp / VlcRelay / Xray），三个出口各有各的开关。
