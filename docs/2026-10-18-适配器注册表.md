## 一、为什么要动

加一个站点，原来要改十个地方：

```text
UserSource.load()          if (isXxx(url)) return wrapXxx(url)
UserSource                 isXxx() + wrapXxx()，200~300 行
UserSource.validate()      白名单，还有一句单独手写的报错文案
UserSource.HTTP_HOSTS      播放解析域名白名单
AiiHttp.get()              一个分支 + 一段 stripOrigin 兜底
AiiHttp.prefetchBody()     同一份分支再抄一遍
新增 XxxAdapter.java       500~1000 行
```

`UserSource` 从 1000 行长到 3701 行，其中 1153 行是「识别 + 生成配置」。同一个故事已经发生过一次：上一版 `SiteRepository` 3959 行，整块删掉重写。

**名单漂移不是假设，已经发生了。** 适配器名单在仓库里有四份（`load()`、`AiiHttp.get()`、`AiiHttp.prefetchBody()`、`validate()`），`porn91` 在 `AiiHttp` 里有三个分支、有 835 行实现，独独漏在 `validate()` 的白名单外 —— 手贴一份 `adapter: porn91` 的配置，`load()` 放行、`validate()` 判「不认识的适配器」，源根本加不进来。

## 二、现在的结构

```text
SiteAdapter.java     一个接口：id / matchesUrl / matchesBody / probe / fetch / check / identity
Adapters.java        唯一一份名单 + 按源取适配器 + /api/ 路径归一化
SiteCfg.java         各站共用的配置拼装小工具（arr / tab / hotTags / 封面域名探测 …）
XxxSite.java         每站一个：怎么认、怎么生成配置、怎么分流、必填项、id 空间
UserSource.java      源配置、源清单、桥指令、代理核心、订阅测速、播放器、读写、校验
AiiHttp.java         HTTP / DoH / 代理 / 缓存 —— 不再认识任何站点名字
```

| 谁 | 管什么 |
|---|---|
| `Adapters.ALL` | 识别顺序。按地址认的排在按形状认的前面（`cms` 在最后） |
| `load()` | 两轮：先问 `matchesUrl`，fetch 一次，再问 `matchesBody` |
| `AiiHttp.get()` / `prefetchBody()` | 各一行：`Adapters.of(profile)` → `actionPath` → `adapter.fetch` |
| `validate()` | 名单和必填项都问注册表，报错文案由 `Adapters.ids()` 拼 |

## 三、加一个站点

**两处：新增一个类，`Adapters.ALL` 里加一行。**

```java
final class ExampleSite implements SiteAdapter {
    @Override public String id() { return "example"; }

    /** 按域名认，认在 fetch 之前 —— 它给的是 HTML，不是 JSON。 */
    @Override public boolean matchesUrl(String url) { ... }

    /** 生成我们内部那份配置。探针不通就抛，别存一份点了没反应的配置。 */
    @Override public JSONObject probe(String url) throws Exception { ... }

    /** origin 非空的源一定会踩「detail 拼了 origin」那个洞，归一化在 Adapters 里做完了。 */
    @Override public byte[] fetch(SiteProfile profile, String path) throws Exception {
        return ExampleAdapter.fetch(path, profile);
    }

    @Override public String check(JSONObject config) { return SiteCfg.checkOrigin(config); }
}
```

```java
static final List<SiteAdapter> ALL = ... new ExampleSite(), ...
```

**顺序有讲究**：`ALL` 就是匹配顺序。按地址认的排前面，`CmsSite` 排最后 —— 它是唯一按响应形状认的，排在前面会把普通 JSON 配置拽进 CMS 那条路。

**不要做的事**：别在 `UserSource` / `AiiHttp` 里补 `if ("example".equals(...))`。`AdaptersTest` 会红。

### 适配器可以有自己的路径，不止那套词汇表

`fetch(path)` 里除了 `home` / `detail` / `episode` / `search` / `category` / `tags` 这些
标准动作，适配器还能自己加路径 —— 它们是**适配器内部的事**，不经过 `web.paths`，
前端直接走 `bridgeCall('detail', { id: '/api/xxx?...' })`。

91porn 的 `/api/reconcile` 就是这么来的：站点网格页的封面和标题是假的（同页一个
viewkey 出现 2~4 次，配不同图），但详情页是准的。于是列表先照网格页返回，前端再
把这一页的 id 一股脑丢给 `/api/reconcile`，Java 用固定线程池并发取详情、回一份
`{id,title,cover,badge}`，前端把卡片和 `state` 里的对象一起改掉。

这类路径的三条纪律：

1. **不能让列表接口变慢**。校正放在第二个请求里，列表该多快还多快（实测首页
   从 8.5s 回到 3.7s，改正在之后 2s 内自己补上）。
2. **并发度压死**（这里是 4）。站点对非浏览器流量有静默处理时，一口气 24 个并发
   有被限流的风险；单条失败就跳过，保留原值。
3. **结果进缓存**（这里的 `META_CACHE` 要 ≥ 一页条数，否则每次进来都全量重拉）。

## 七、真站验证（mrds66，2026-10-18）

新加了 `Mrds66LiveTest`（8 条，默认跳过，`-Dhg.live=1` 才跑），走完「识别 → 生成配置 → 过校验 → 首页 → 分类 → 详情 → 播放」整条链。

```bash
./gradlew :app:testDebugUnitTest --tests '*Mrds66LiveTest*' -Dhg.live=1
```

第一次跑，7 条里挂 1 条，另有一条暴露出真问题：

### 已经坏掉的：okhttp 默认 UA 被 CloudFront 挡

同一个站，同样一台机器，只换 UA：

```text
GET /                      UA=okhttp/4.10.0 → 200
GET /category/mrds/        UA=okhttp/4.10.0 → 403
GET /archives/431273.html  UA=okhttp/4.10.0 → 403
GET /tag/吃瓜/             UA=okhttp/4.10.0 → 403
以上四条                  UA=Dalvik / 安卓 Chrome → 全 200
```

**首页 200 是最坏的那种坏法**：探针打的就是首页，所以「加源」一定成功、首页一定有卡片，点进任何一个分类或详情才 403。旧注释里写着「这个站不查 UA，实测四种都 200」—— 那是 10-16 的事，10-18 已经不是了。

修法：`SiteCfg.browserHeaders()` 出一份浏览器头，mrds66 的 `get()` 和探针都带上；porn91 原来自己维护一份同款头，改成复用（它踩的是同类问题，只是挡法更阴 —— 200 但 0 字节）。

### 环境问题，不是适配器问题

真机上（23113RKC6C，MIUI / Android 16）连不上 `www.mrds66.com`：`adb shell curl` 25 秒 connect 超时，TCP 都没建起来。App 的表现是对的 —— 卡 40~50 秒后给出「没认出这是每日大赛……站点可能改版、被墙，或者填的不是这个站」。

两个可以再改的地方（这次没动）：

- 探针 20 秒超时，叠上 OkHttp 的多路由重试，首包要等 40 秒才失败。探针这种「先探通再存」的动作，8~10 秒足够。
- 设置源那个按钮在等待期间只有「正在获取…」，没有「网络慢时最多等 N 秒」。卡 40 秒没有任何进度反馈，用户会以为死机了。

### 又一条：封面是 AES 密的，不是图片

上一轮判定「被墙」之后，给手机开了一条代理（`adb reverse` 把 Mac 的 Clash 7897 映到手机的 127.0.0.1:7897），加源立刻成功。然后看见首页卡片全是灰底 + 标题首字，一张图都没有，日志：

```text
GET pic.jtzatly.cn/upload_01/xiao/2026…/…jpeg
cover failed
java.lang.IllegalStateException: 封面解密结果无效
```

拉下来一看，那 214048 字节不是图片：

```text
4d 3c d8 41 d3 9b 11 79 …     Content-Type: binary/octet-stream
```

站点自己在 `/usr/plugins/tbxw/js/zzz.js` 的 `decryptImage()` 里解，键和 IV 是两串
ASCII 码拆出来的（`'57_55_98_…'.split('_').map(fromCharCode).join('')`）：

```text
key = f5d965df75336270
iv  = 97b60394abc2fbe1     ← 注意：内置模板是 97b60374abc2fbe1，差一个字符
AES-128-CBC + PKCS7
```

所以 `cover.mode` 从 `plain` 改成 `aes-cbc`，密钥按站点那份填。改完首页、详情页的图都出来了。

**别把两套密钥混用**：内置模板（黄果那套）的 IV 是 `97b60374…`，每日大赛是 `97b60394…`，抄错一位就是「封面解密结果无效」。

### 还有一条：简介开头带半个标签

详情页第一行显示成 `class="post-content" itemprop="articleBody">每日大赛最新地址…`。
`description()` 的切片起点定在 `class=` 上，前面那个 `<div ` 被 `stripHtml` 吃掉了，
后半截属性却因为不在 `<…>` 里留下来。起点挪到 `<` 就好，补了一条离线回归。

## 八、真站验证（missav，2026-10-18）

完整过程见 `docs/2026-10-18-missav-适配器.md`。这一节只留**对所有适配器都成立**
的那几条，因为它们是这次最贵的东西 —— 七个 bug 有五个的表现完全一样：

> **接口 200、日志无异常、界面一片空。**

### 适配器契约是两半，少一半等于没做

一半是**响应形状**（前端 `asArray(shapeValue(raw, …))` 认哪种信封），
另一半是**配置里的 `web.fields` 别名表**。两半都在才叫接上了。

`fields` 漏一个角色，前端 `pick(obj, role)` 就取空，而且不报错：

| 漏了 | 界面上的表现 |
|---|---|
| `episodeNumber` | 「无法拉到集数」（唯一的集被 `filter(Boolean)` 滤掉） |
| `source` | 「未取得播放地址」 |
| `tagName` | 「全部类型」每个胶囊写成 `dm96/高清`（fallback 到 slug） |

**规矩：适配器返回什么键名，别名表里就必须声明同名候选。**

### 列表页的翻页字段是有约定的位置的

`nextPageOf` 只读 `shapeValue(raw,'list','page','pagination.page')` / `…pages…`。
要么按默认形状返回 `{pagination:{page,pages}}`，要么在配置里写
`web.shapes.list = {page:"…", pages:"…"}`。只给一个 `hasMore` 不够 ——
前端不看它，界面会一直写「已经到底了」。

### 索引页不能当作品列表接

`/cn/genres`（分类索引）、`/cn/actresses`（女优）、`/cn/makers`（片商）都不是
作品列表。把它们塞进 `ui.tabs`，点开必然是「已显示 0 部」——
因为 `parseList` 在那种页面上认不出影片卡片。

进导航的每一项都必须是「一页影片」。索引类的东西走 `tags` 那条路
（`renderTags` 是专门为「一堆可点的名字」准备的页面）。

### `web.categories` 是第二张容易漏的表

子分类的配置是 `ui.categoryIds[key] = [slug…]` 加 `ui.categoryLabels[key] = [名字…]`，
两个数组等长。但 `cateIdOf(slug)` 查的是 **`web.categories`**，而
`apiPathFor` 里 `if (!cateId) return null` 会**静默放弃请求** —— 少填一个 slug，
症状是「点了那个子标签，页面还停在上一页」，没有任何报错。

### 配置生成要能离线测

`probe` 里「拼配置」那段没有网络依赖，抽成 `static buildConfig(base, html)`
之后，`MissavConfigTest` 拿真实首页 fixture 就能把整份形状钉住 ——
上面五条里有四条是它当场能拦下来的。少一个字段是编译后的第一个测试红，
不是真机上一轮装包加点按才发现。
